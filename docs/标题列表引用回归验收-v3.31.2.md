## 3. 新发现：FMT-4（P3）

### 3.1 现象

**当行内格式包裹在链接外壳之外时，再次点击同一格式按钮不会取消格式，而是再套一层，导致链接被破坏、界面显示字面源码。**

### 3.2 最小复现（三容器 100% 命中）

```
1. 引用块输入：引用块内的文字内容
2. 选中 → 加粗 B      → > **引用块内的文字内容**
3. 选中 → 链接 🔗     → > **[引用块内的文字内容](https://x.com/demo)**
4. 选中 → 再加粗 B    → > **[**引用块内的文字内容**](https://x.com/demo)**   ← 预期：取消加粗
   界面显示：[引用块内的文字内容](https://x.com/demo)   ← 链接失效，源码字面可见
```

### 3.3 覆盖范围（`_m84` / `_m85` 实测）

| 格式 | 标题 | 列表项 | 引用 |
|---|---|---|---|
| bold | ❌ 复现 | ❌ 复现 | ❌ 复现 |
| italic | ❌ 复现 | ❌ 复现 | ❌ 复现 |
| strike | ❌ 复现 | ❌ 复现 | ❌ 复现 |
| mark（高亮） | ❌ 复现 | ❌ 复现 | ❌ 复现 |
| code | 另类表现：第 3 步加链接被 FMT-1 守卫拒绝（raw 不变），第 4 步取消行内码 → 最终无链接 | 同左 | 同左 |

**对照（正常）**：反向顺序「先链接 → 再加格式 → 再点同格式」**可以正确取消**——
`_m84` A 组 6/6 PASS：`[文字](url)` → `[==文字==](url)` → `[文字](url)`。
`_m83` 亦验证「先链接再叠加 5 种格式」三容器 30/30 正确（标记落在链接文字内部，如 `[==文字==](url)`，渲染正常）。

### 3.4 根因（推断，待代码确认）

toggle 的「是否已包裹」判定检查的是**紧邻选区两侧的字符游程**。当结构是 `**` + `[` + 文字 + `](url)` + `**` 时，紧邻选区的是 `[` 与 `]`，标记字符被链接外壳挡住，判定为「未包裹」→ 执行包裹；且包裹位置落在链接文字内部，于是产生 `**[**文字**](url)**`。

> 参考：v3.31.2 已为 `***粗斜***` 落地「外侧同字符游程左右平衡时允许解包」的 LIFO 解包逻辑（editor.html:2894），FMT-4 属同一机制的未覆盖分支（链接外壳未参与平衡检测）。

### 3.5 影响与建议

- **影响范围**：窄（需「格式 → 链接 → 再点同格式」这一特定序列），但结果**可见**（链接变字面源码），用户可感知；可通过再点一次「清除格式（T×）」自愈（`_m81` I5 已验证嵌套组合可清除）。
- **优先级**：**P3**（不丢数据、可自愈、触发序列特定）。
- **修复方向**：unwrap 判定时跳过链接外壳（`[`…`](url)`）后再做游程平衡检测，复用 v3.31.2 已有的 LIFO 解包写法。

### 3.6 修复记录（v3.31.2 · 2026-09-29 晚）

**改动位置**：`src/editor.html` `wrapSelection()`（约 2891 行，toggle 判定段）。

**改法**：判定「是否已包裹」前先把链接外壳纳入区间 ——

```js
var _lkT = raw.slice(b).match(/^\]\([^)\n]*\)/);
var _oa = a, _ob = b;
if (raw.charAt(a - 1) === '[' && _lkT) { _oa = a - 1; _ob = b + _lkT[0].length; }
```

后续 `prevCh / nextCh / _lr / _rr / 包裹判定 / 解包拼串` 全部改用 `_oa / _ob`：

- **无链接外壳时** `_oa/_ob` 恒等于 `a/b`，与原语义逐字节一致（`_m81` 173 项、`_m83` 19 项无回归）；
- **`**[文字](url)**` 形态**：紧邻选区的 `[` 与 `](url)` 被收进判定区间，外侧的 `**` 被识别为同一对标记 → 解包**外层**标记、链接本体整条保留 → `[文字](url)`；
- 解包后选区仍落在链接文字上（`setCaretSel(el, a - mlen, selected.length)`），连续操作所见即所得。
