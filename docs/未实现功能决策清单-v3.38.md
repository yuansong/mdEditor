## 二、A 档 —— 建议做（我会直接开工，你点头即可）

### A1. UNDO-1 源码态落回不清空重做栈（**这是缺陷，不是新功能**）

| 项 | 内容 |
| --- | --- |
| 现象 | 撤销到旧态 → 进源码态整体改写 → 退出源码态 → 按 Ctrl+Y，**源码改写被旧 redo 条目静默覆盖**，用户源码改动无提示丢失 |
| 根因 | `setSourceMode(false)`（`editor.html:6958-6966`）整体替换文档后只重置 `lastSnapshot`，**没清空 undoStack / redoStack**；而 `setMarkdown`（6598-6599）是双栈清空口径 —— 两处对「整体替换文档 = 撤销历史作废」的定义不一致 |
| 代价 | **0.5 小时**（exit 分支补两行） |
| 风险 | 极低；唯一需要你拍板的是：清双栈（历史作废）还是只清 redoStack（保留跨源码改写的撤销能力） |
| 建议 | **做，且按 setMarkdown 同口径清双栈**（一致性优先，也最不容易出意外） |

## 三、B 档 —— 请你挑（有明确收益，但要您先定策略）

### B1. TAB-7 固定标签（Pin）

- 固定的标签：关闭类操作跳过、图标收窄、强制排左。
- 代价 1 天；风险点是**与既有批量关闭语义的交叉**（「关闭其他所有」要跳过固定项、索引修正要重算）。
- **需要你定**：固定标签是否也参与「关闭所有未修改」的跳过？我的建议：**跳过**（固定的语义就是"不许自动关"）。

### B2. TAB-8 Ctrl+Tab 标签快切面板（MRU）

- 代价 1~2 天（Qt 需自绘无边框浮层 + 维护 MRU 序列）。
- **需要你定**：标签常态数量大概多少？若日常 ≤5 个，收益有限，**建议缓做**；若经常开 10+ 个，值得做。

### B3. SYN-3 分屏滚动同步是单向的

- 现状：源码侧滚动会带动预览；**拖动预览滚动条，源码侧不动**。
- 反向映射（预览块 → 源码行）成本中等。
- **需要你定**：分屏的定位是「左写右看」（那么单向够用，文档说明即可）还是「双向对等」？
- 建议：**若你日常不用双栏，就关闭该项并销账**（写进文档说明）。

### B4. MMD-8 引用块内图表的编辑路径

- 渲染已实测出图，但「点进去编辑」这条路径没实测、也没提示。
- **需要你定**：引用内嵌块的编辑策略（是否允许在引用里编辑图表）。定了才谈实现。

### B5. OBS-N1 `*A**B*` 强调闭合（解析层最后一块硬骨头）

- 现象：`*A**B*` 这类「同一个游程既可闭合又可开启」的输入，朴素配对会残留一个裸 `**`（模糊测试基线里就剩这 1 例）。
- 根治需要**引入 CommonMark 式 delimiter 栈**。**本批试过并已回退**：栈化改造虽然修好了样本，但让模糊测试 FAIL 从 1 恶化到 **13**（`~~` / `==` / `<u>` 只能靠按强调边界切分的碎片递归，开闭边界被割裂）。最终改用最小修复 `findRunClose` 恢复基线。
- **需要你定**：是否接受「当前最小修复 + 保留 1 例已知边界」，把 delimiter 栈作为**独立版本**（含完整回归预算）专项？
- 建议：**先不做**。收益（极端嵌套输入）远小于风险（解析层是全局共享底层，一改全炸）。若要做，请单独排一个版本，我会先写对照模糊测试再动代码。
