## 一、功能与交互规范分析

### 1.1 定位与使用场景

分割线在本产品的定位是 **Markdown 原生块级分隔符**（CommonMark *thematic break*），不是 UI 组件库意义上的 Divider 组件——它的形态完全由 Markdown 源码 `---` 决定，不存在独立的可配置属性层。

| 场景 | 支持度 | 说明 |
|---|---|---|
| 章节 / 内容分区 | ✅ 主场景 | 文档主体最常用的语义分隔 |
| 列表分组 | ✅ | 列表块后的 `---` 独立成块，不与列表粘连（S10 实测：`- 甲\n- 乙\n\n---\n\n丙` 三块分明） |
| 正文与附录 / 脚注区 | ✅ | 与 footnotes、deflist 混排正常 |
| 封面 / 元信息分隔 | ✅ | 首块即 hr 时导航进入不切源码态（T6 实测） |
| 引用内部 | ✅ | `> ---` 渲染为 quote 内嵌 hr（S9 实测 `hrInQuote=true`） |
| 表单分隔 | ➖ 不适用 | 本产品为 Markdown 编辑器，无表单构建能力 |
| **行内 / 纵向分隔** | ❌ **不支持** | 无竖线形态（S8 实测：hr 元素无 class、无 data-* 变体属性） |
| **单元格内分隔** | ❌ **不支持** | 7964 明确：`CELL_SLASH_IDS = ['list','code','image','chart','math']`，hr 不进单元格菜单，兜底无副作用 |

### 1.2 语法支持矩阵（实测 6/6 通过）

识别正则：`editor.html:1493` `/^\s{0,3}(?:[-*_]\s*){3,}$/`

| 语法 | 实测 | 说明 |
|---|---|---|
| `---` | ✅ | 规范写法 |
| `***` | ✅ | 星号等价 |
| `___` | ✅ | 下划线等价 |
| `----`（4+） | ✅ | 数量 ≥3 即匹配 |
| `- - -`（空格分隔） | ✅ | 允许标记间空格 |
| `   ---`（缩进 3 空格） | ✅ | 允许 ≤3 空格缩进 |

> **边界**：列表项之间的裸 `---`（`- 甲\n---\n- 乙`）**不会**被拆成独立 hr（S10b 实测块序列仍为单块 `["P[甲--乙]"]`），与 CommonMark「setext 优先 / 列表懒惰延续」一致，属正确行为。

## 三、竞品对比

### 3.1 对比对象

- **Ant Design 6.0 Divider**（组件库标杆，配置项最全）
- **Material Design（M1/M2/M3）Dividers**（设计语言标杆，规格最严谨）

### 3.2 视觉规范对比

| 维度 | 本产品 | Ant Design 6.0 | Material Design | Typora / Notion |

| 间距 | `margin: 2em` 固定 | `size`: small / medium / **large** 三档 | 由布局规范决定 | 固定（Typora ~2em） |

| 可访问性 | 原生 `<hr>` 隐含 `role=separator`；**无键盘选中路径** | 需开发者自行标注 | 明确声明「装饰元素，无需特殊无障碍处理」 |
| 状态数 | 2（默认 / 选中） | 静态（无交互态） | 静态 |
| 文档完整度 | 内部清单（HR-1~7 已修）+ 本报告 | API 表 + 示例 + Design Token 表 + 语义 DOM | 规格（厚度/透明度/位置）+ 用法 + Do/Don't + 代码 |
| 使用指引 | ❌ 无「何时用/何时不用」 | ✅ When To Use + Do/Don't | ✅ Do/Don't 图例 + 滥用警示 |

> **值得借鉴的一点**：Material Design 明确给出「过度使用分隔线会产生视觉噪音、削弱分隔意义，优先考虑留白、子标题或 inset 分隔线」的**反向指引**。本产品既无正向使用建议也无反向约束，帮助文档中分割线条目缺失。

## 四、缺失与薄弱项、改进建议（按优先级）

### 4.1 新登记缺陷

| 编号 | 优先级 | 问题 | 位置 | 建议 |
|---|---|---|---|---|
| **HR-8** | **P3** | ① **术语不一致**：编辑器/主菜单用「分割线」（`editor.html:8620`、`mainwindow.py:519`），`/` 菜单配置面板用「分隔线」（`dialogs.py:28`）；② **导出配色硬编码**：`exporters.py:459` `hr{...border-top:1px solid #ddd...}`，6 套主题的分割线色在 HTML/EPUB 导出后统一退化为 `#ddd` | 见左 | ① 全局统一「分割线」；② 导出 CSS 按当前主题注入 `--border` 对应色值（导出器已有主题上下文可复用） |
| **HR-9** | **P3** | **无视觉变体与间距档位**：线型仅 solid、粗细固定 1px、间距固定 2em、无 inset 缩进；窄屏 2em 偏大 | `editor.html:92-95` | 提供**最小可用扩展**：支持 HTML `<hr>` 上写 `data-variant=dashed/dotted`、`data-size=tight/normal/loose`（与围栏 `st=/lnum=` 同款属性持久化思路），在风格弹层或块菜单二级中提供；窄屏（<640px）间距降为 1.5em。**不做**纵向分隔线（超出 Markdown 编辑器定位） |

### 4.2 明确的"不做"项（附理由）

| 项 | 竞品 | 不做理由 |
|---|---|---|
| 纵向（竖线）分隔 | AntD `vertical`、MD VerticalDivider | Markdown 无对应语法；引入需扩展 HTML 存储，与「存储形态不漂移」原则冲突，收益低 |
| 内嵌文字标题 | AntD `children` + `titlePlacement` | Markdown 无此语法；「带文字分隔线」在 Markdown 编辑器中实际由 `## 小标题` 承担 |
| 单元格内分割线 | — | 单元格语义空间有限，且 7964 已明确排除，兜底无副作用 |
| 自动补全 / 智能插入 | — | 超出 Markdown 编辑器定位（与代码块模块 CODE 系列同一判断口径） |

### 4.3 优先级汇总

```
P3  HR-8  术语统一 + 导出配色随主题        —— 半天，零风险，建议随任意小版本捎带
P3  HR-9  视觉变体最小扩展（虚线/点线/间距）—— 1 天，需定存储方案（HTML hr 属性扩展）

P4  HR-11 使用指引与 toast 文案补全        —— 半天
——  不做  纵向分隔线 / 内嵌文字 / 单元格内  —— 见 4.2
```

### 4.4 相对竞品的保留优势

| 项 | 说明 |
|---|---|
| 删除路径最完整 | 3 条删除路径（选中 DEL/BS、块菜单删除块、下方段行首 Backspace）+ 撤销，竞品作为纯展示组件无此能力 |
