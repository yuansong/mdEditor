## A. 需要产品决策（技术可行，但不应由开发侧单方面定）

### A1. P1-5 数据埋点 / 本地用量统计
- **内容**：本地 SQLite 记录 app_start / 活跃天 / 导出成败 / feature_use 计数；后续可选匿名遥测 opt-in。
- **暂缓原因**：纯本地统计技术上可行（1~2 天工作量），但**是否收集、收集什么、是否上报**是产品定位与隐私承诺问题——mdEditor 的差异化根基是"本地优先、数据自主"，埋点方案必须先定隐私红线文案。
- **前置条件**：① 确认北极星指标与最小事件集（清单 §7 已给草案）；② 明确"纯本地不上网"是否够用；③ 遥测若上报需选定服务端。
- **建议**：下一版本先落**纯本地统计**（无隐私争议），设置页给"使用报告 + 一键清空"；匿名遥测单独立项。

### A2. P1-6 商业化路径
- **内容**：赞助入口 / 模板主题增值包 / 云同步付费服务。
- **暂缓原因**：商业化是战略决策（定价、底线承诺、服务端投入），且依赖 P1-5 的数据验证需求。
- **前置条件**：P1-5 本地统计上线并观察一个迭代周期；明确"编辑器永久免费 + 真 .md 保真 + 不强制账号"三条底线写入对外承诺。
- **建议**：先做零成本赞助入口试水意愿信号；增值包等模板/主题生态成型后再评估。

### A3. P1-8 用户反馈与社区闭环
- **内容**：帮助菜单「反馈与建议」（mailto / 表单 / 社群二维码）、关于页更新公告渠道。
- **暂缓原因**：需要真实可达的反馈渠道资产（邮箱地址 / 表单链接 / 群二维码 / GitHub 仓库），当前均不存在，写死占位反而是负体验。
- **前置条件**：确定并开通至少一个官方反馈渠道。
- **建议**：渠道就位后半天即可接完（菜单项 + QDesktopServices 打开链接）。

### A4. P0-6②③ 安装器与代码签名
- **内容**：NSIS/Inno Setup 安装包、开始菜单/卸载项、.md 文件关联；EV 代码签名证书消除 SmartScreen。
- **暂缓原因**：① 签名证书需要采购决策与年费；② 安装包脚本与 CI 需要一次性投入，且当前仍为 zip 手工分发，先落地了 ①（检查更新）打通"触达"链路。
- **前置条件**：分发方式决策（官网 / 网盘 / 应用商店）；签名预算。
- **建议**：先上 Inno Setup（免费）做安装包 + `.md` 关联，签名随正式发布节点采购。

### A5. P2-5 多设备同步 / P2-6 移动端
- **内容**：WebDAV/同步文件夹通道；导出自包含 HTML 便于手机查看；原生移动端。
- **暂缓原因**：依赖 P1-6 商业化验证结果；移动端属远期。
- **前置条件**：A2 决策；P0-7 归档（已落地）先验证用户的备份需求强度。
- **建议**：P2-6 的"导出自包含 HTML"其实已基本具备（IMG-2 内嵌 + MMD-3 静态 SVG），可在 README 增加"发给手机看"教程，零开发成本。

## B. 需要较大开发投入（单独立项排期）

### B1. P0-4② 块级公式导出 Word/EPUB 图片化（MATH-2）
- **内容**：KaTeX→SVG/PNG 内嵌，替换"仅留 LaTeX 源码"的降级。
- **暂缓原因**：渲染管线改动较大（编辑器侧需批量把 math 块转位图并传回 Qt，类似 MMD-2 的导出接力），估 3~5 人日；本轮以"自检提示"先止血。
- **前置条件**：无硬性前置；建议复用 `__mmdExportStart/State` 接力机制。
- **建议**：列入 v3.33 首位——学术交付是核心人群（A1 假设）的最高频痛点。

### B2. P1-10②③ 导出预览
- **内容**：PDF 打印预览（Qt Print Support）；Word"导出后自动打开"。
- **暂缓原因**：PDF 预览需引入打印预览对话框与样式适配；Word 自动打开与"打开该文件"收尾动作（已落地）功能重叠。
- **前置条件**：B1 完成后再评估（预览的价值是提前看到降级，降级项本身先补齐）。
- **建议**：Word/EPUB 已有自检 + 导出后打开，PDF 预览可与打印功能合并排期。

### B3. P2-1 用户自定义模板与片段库 ｜ ✅ 已实现（v3.33）
- **内容**：用户保存自己的重复结构，接入 `/` 菜单「模板」。
- ~~**暂缓原因**~~：已于 v3.33 落地（dist58）——`%APPDATA%/mdEditor/templates.json` 持久化 + 系统设置→编辑器→斜杠菜单组「管理…」（列表 / 新建 / 编辑 / 删除 / 上移 / 下移）+ ⭐ 追加到 `/` 菜单「模板」二级与悬浮栏「📄 插入模板」按钮，与内置模板同款交互。验证：`tests/_m97.py` 16/0。
- **v3.36 增量（TPL-E）**：内置模板并入统一列表（`templates.json` 升 v2，旧文件自动迁移）；管理入口提升为设置**一级页「模板」**（与外观/编辑器/通用同级，模态对话框改写为内嵌页，改动即时落盘）；新增「需求文档」「设计文档」两个内置模板（共 8 个）；**悬浮栏「📄 插入模板」按钮已移除**，模板入口收敛为 `/` 菜单「模板」二级。验证：`tests/_m102.py` 43/0。
- **遗留**：导入 / 导出模板包（分享）暂未做，可在模板生态阶段补充。

### B4. P2-3 AI 辅助（用户自带 Key）
- **内容**：校对/润色/摘要/标题生成，块内触发。
- **暂缓原因**：大功能（流式 UI、提示词、多服务商适配）；且必须与"明确不上传"的隐私承诺一起设计。
- **前置条件**：主流程补齐（P0 全清）+ 隐私设计评审。
- **建议**：远期；若做，从"选中文本 → 右键润色"最小场景起步。

### B5. P2-4 主题生态（用户自定义 CSS）
- **内容**：用户主题目录 + 导入/分享。
- **暂缓原因**：六套内置主题的 QSS 变量体系需先稳定为可注入的接口；社区尚不存在。
- **前置条件**：A3 社区渠道；QSS 变量化改造。
- **建议**：先支持单文件 CSS 覆盖（`%APPDATA%/mdEditor/themes/custom.css`），不做管理界面。

## C. 低成本快办项（建议随下个版本顺手落地）

### C1. P1-4①② 命令面板"最近使用"排序 + 每日一提示
- **内容**：面板按本地使用计数排序；首月展示可关闭的 Tip of the day。
- **暂缓原因**：本轮聚焦 P0；单项成本低（各 <1 人日）但量大。
- **建议**：与 C2 一起打包为"可发现性"小版本。

### C2. P1-4③ 设置页搜索框（工程清单 #22）
- **内容**：设置对话框顶部过滤框。
- **暂缓原因**：同上；且设置页 QSS/分组有既定打磨计划（#23/#24/#30 同批）。
- **建议**：随 P2-8 打磨批次一起做。

### C3. P1-9 性能边界向用户明示
- **内容**：搜索达上限时结果区提示"已达上限"；超 400 块 toast"已启用长文档优化"；大图插入给压缩建议。
- **暂缓原因**：需要动内核（editor.html 搜索结果区 / collect 轮询）多处 UI 文案，且边界值文案要与既有上限配置核对，本轮未及；**非不可实现**。
- **前置条件**：无。
- **建议**：v3.33 随 B1 一起做；先从"搜索达上限提示"开始（纯文案，半小时级）。

### C4. P2-7 无障碍专项检查
- **内容**：高 DPI、键盘全流程可达、对比度、读屏支持核查。
- **暂缓原因**：属"检查 + 修补"专项，需要完整不受打扰的一轮；键盘可达性在菜单/快捷键体系上基础较好。
- **建议**：排一次专项会，产出问题清单后按 P2-8 批次修补。

### C5. P2-8 设置页打磨遗留（#22/#23/#24/#30）
- **内容**：设置搜索 / 自定义强调色 / 正文字体行距 / 快捷键速查卡。
- **暂缓原因**：打磨项，随版本打包处理。
- **建议**：v3.34。
