## 一、交互逻辑梳理：数据流与事件传递机制

### 1.1 两个模块的架构位置

| | 文件列表 | 大纲 |
|---|---|---|
| 宿主 | Qt 侧 `Sidebar`（sidebar.py:260），QListWidget 一级浏览 | Qt 侧 `OutlineTree`（QTreeWidget，sidebar.py:233，支持同级拖拽） |
| 数据来源 | 本机文件系统（os.listdir / GetLogicalDriveStringsW） | 编辑器内核 `window.getOutline()`（editor.html:6575） |
| 与编辑器的关系 | 间接：打开/切换文档时由 Python 主动 `set_root` | 实时：每秒 poll 上报，内容变化自动重建 |

### 1.2 大纲数据流（JS → Qt 单向 + 点击回传）

```

  └─(每秒) collect():7218 → JSON.outline = getOutline():6575
      getOutline(): 遍历 h1~h6 块 → {index(块序号), level, text(纯文本≤60字),
                    end(节结束块序号), words(分节字数，OUT-1 纯文本口径)}
  └─ Python _poll → _on_collect (mainwindow:1673-1675)
      → self._outline_cache（缓存，供拖拽对账）
      → sidebar.set_outline(headings) (sidebar.py:662)
          ├ 签名去重：json([[index,level,text]]) 相同则跳过（防闪烁/防丢点击，#8）
          ├ 重建树：层级挂靠（h4→最近 h3）、1~(级别-1) 级默认展开
          ├ 按 index 恢复选中（递归 find，706-724）
          └ 分节字数后缀原地 setText（不重建树，#8）

点击大纲项 sidebar._on_outline_clicked (567)

      → 编辑模式：view.gotoHeading(i) (6612) — scrollIntoView(smooth) + flash 1.6s，不进编辑态
      → 分屏模式：view_src.gotoHeadingSrc(i) (6430) + view_prev.gotoHeading(i) 【双视图显式同步】

拖拽调序 OutlineTree.dropEvent (243，同父同级 + 项间落点)
  → _on_outline_dropped (749)：按新视觉顺序从 _outline_cache 取 [index,end) 区间
     （缓存缺失即放弃——防内容刚变时错切）
  → win.reorder_sections(pairs) (1088) → view.reorderSections (6625)
     连续性校验（按原始位置排序后首尾相接）→ 整段重排 state.raw
```


### 1.4 两模块与编辑器的三方联动时序

| 触发 | 文件列表反应 | 大纲反应 |
|---|---|---|
| 打开/切换文件 | set_root：目录跳转 + 高亮（即时） | 下轮 poll（≤1s）重建树 |
| 切换到未命名 | **无反应（残留，OUT-3）** | 下轮 poll 重建 |
| 编辑正文 | 无 | ≤1s 签名比对后增量/重建 |
| 编辑标题文本/增删标题 | 无 | 同上（index 变化 → 树节点 index 全部更新） |
| 大纲拖拽 | 无 | reorderSections 改 raw → 下轮 poll 重建（已含新顺序） |
| 删除/重命名文件（右键） | 刷新列表；当前文件联动标签 | 若删的是当前文件：poll 继续，大纲仍显示旧内容（文件已不在盘上，保存会重建同名文件——sidebar._file_delete:839 有警示文案） |

### 1.5 设计要点与已知取舍

- **签名去重**（#8）：大纲轮询每秒全量上报，Qt 侧按 [index,level,text] 签名跳过重建——字数变化只原地 setText。这套「JS 全量算、Qt 侧去重」的架构规避了闪烁与点击丢失。
- **拖拽防错切**：`_on_outline_dropped` 发现缓存与树不一致（index 不在 ends）直接放弃调序——内容刚变时的保护，但不覆盖「跳转」路径（见 OUT-4）。
- **大纲 index 是「上报时刻」的块序号**：整个大纲系统只有 1 秒时差窗口，这是竞态（OUT-4）的架构根源。

## 三、竞品调研：启动默认行为

### 3.1 是否默认打开上次编辑的文件？

| 编辑器 | 启动行为 | 证据 |
|---|---|---|
| **Typora** | 官方「Launch Options」**四选一**：打开新文件（默认）/ 恢复上次关闭的**文件夹** / 恢复上次关闭的**文件和文件夹** / 打开自定义文件夹。Windows/Linux 另有「启动时重新打开最后一个文件」选项 | 官方支持页 support.typoraio.cn/Launch-Options |
| **Obsidian** | vault 级：**默认恢复上次退出的 vault**（官方论坛确认，无「默认 vault」概念）；文件级：v1.11.0（2025-12）正式设置「文件与链接 → 默认打开的文件」：**上次打开的文件** / 新笔记 / 指定笔记 / 日记 | obsidian.md/changelog/2025-12-10；官方论坛 |
| **VS Code** | `window.restoreWindows` **默认 all**：恢复上次全部窗口、标签页，已保存文件连**光标位置和滚动偏移**都恢复 | VS Code 官方设置（多处社区文档交叉印证） |
| **mdEditor 现状** | 无参启动 = 空白未命名文档；仅两条恢复通道：**命令行文件参数**、**未命名文档影子草稿**（P0-1，弹窗询问，只救未保存内容）；侧栏文件列表从「此电脑」层开始，不记忆任何上次状态。QSettings 实证 18 个键（codeLang/fileListMode/outlineLevel/recentFiles…）中**无 lastFile/lastSession 类键** | `_m107` S0 + QSettings allKeys 实证 |

**结论**：「会话恢复」是三大主流编辑器的共同标配，且恢复粒度不止文件本身——Typora 连侧栏文件夹定位一起恢复，VS Code 恢复到光标位置，Obsidian 恢复 vault+文件+界面状态。mdEditor 有「最近文件」菜单（recentFiles 前 10 条）作为手动补偿，但无自动恢复。

### 3.2 文件列表是否默认选中上次选中项？

| 编辑器 | 侧栏/列表恢复 |
|---|---|
| Typora | 「恢复上次关闭的文件夹」= 侧栏文件树回到上次目录定位（与文件恢复绑定同一设置） |
| Obsidian | 文件浏览器恢复上次展开目录与选中文件（会话状态随 vault 持久化） |
| VS Code | 资源管理器恢复上次展开状态与活动文件选中/高亮 |
| **mdEditor 现状** | **否**。启动永远从「此电脑」层开始；运行期内确实「跟随当前文档并高亮」（S1 实证，这部分是健康的），但该状态只在会话内存活 |

**结论**：竞品三家的侧栏定位/选中状态都随会话恢复（或与文件恢复绑定）；mdEditor 的「跟随当前文档 + 高亮」机制运行时正确，但启动后完全归零。

## 四、差距总结与改进建议

### 4.1 差距总结

| 维度 | 现状 | 竞品水位 | 差距评级 |
|---|---|---|---|
| 启动恢复上次文件 | 无（只有命令行参数 + 草稿救援） | Typora/Obsidian/VS Code 均为官方设置项 | **大** |
| 侧栏定位/选中恢复 | 无（会话内正确，重启归零） | 三家均随会话恢复 | **大** |
| 文件列表跟随当前文档 | ✅ 运行时正确（set_root + 高亮） | 同 | 持平 |
| 大纲实时性 | ≤1s poll + 签名去重，运行时体验良好 | 同 | 持平 |
| 大纲跳转/调序 | ✅ 运行时正确；有 1s 竞态窗口（OUT-4） | Typora 同为渲染层直读，无此窗口 | 小 |
| 跨标签状态一致性 | 未命名标签残留上一文件高亮（OUT-3） | —（多数竞品无多标签概念） | mdEditor 特有 |

### 4.2 改进建议（按优先级）

**G1（P2，1~2 天）｜启动会话恢复——补齐最大差距**
系统设置→通用 增「启动时」选项组，对齐 Typora Launch Options 四档：
①打开放置文档（现状默认）；②恢复上次文件；③恢复上次文件 + 侧栏位置；④打开指定文件夹。
实现要点：QSettings 增 `lastFile`（`_load_path`/`_on_tab_clicked` 时写）、`lastSidebarDir`/`lastSidebarFile`（`set_root` 时写）；启动流程在 `check_draft_recovery` 之前按档位执行；草稿救援优先级高于会话恢复（两者可叠加）。

**G2（P3，2 小时）｜OUT-3 修复：未命名标签清侧栏残留**
`_on_switch_capture` else 分支补 `sidebar.clear_current_file()`：保留 `_cur_dir`（目录上下文仍可能有用），仅清 `_cur_file` + `setCurrentRow(-1)` 取消高亮。

**G3（P3，半天）｜OUT-4 修复：大纲跳转校验**
`gotoHeading(i)`（6612）入口加校验：`blockInfo(state.raw[i])` 为标题且纯文本与调用方传入的期望文本一致，不一致则按文本在 `state.raw` 重查 index（同 renumberFootnotes 的跳过围栏范式）。Python 侧 `jump_to_heading` 把 `item.text(0)` 一并传下（注意剥字数后缀「　·　N 字」）。

**G4（P4，1 小时）｜OUT-6 对齐：分屏下调序双视图下发**
`reorder_sections` 与 `jump_to_heading` 对齐，dual 时补发 `view_prev.reorderSections`；或维持 poll 收敛并在注释注明延迟取舍。

**G5（P4，随帮助文档批次）｜大纲与文件列表使用指引**
帮助面板补：大纲拖拽仅限同级、index 时差窗口说明、文件列表 blank 模式的来源（系统设置→通用）。
