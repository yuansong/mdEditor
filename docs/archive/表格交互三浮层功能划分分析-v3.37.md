## 一、现状盘点：表格编辑实际存在四个（外加一个隐含）交互面

| 交互面 | 唤起方式 | 表格场景下的内容 | 代码锚点 |
|---|---|---|---|
| **格式栏 floatbar**（悬浮格式命令） | 选中文字（160ms 防抖） | B / I / U / S / 高亮 / 行内码 / 链接 / 清除格式；单元格内选区额外多一个「＋」按钮；尾部显示选字数 | `buildFloatbar` 7374-7433；单元格走 `applyCellFloat` 专用映射 7881-7886 |
| **对象操作条 objbar**（悬浮命令标注） | 点击任一单元格（表格即整块选中） | 仅「标注」一个按钮，悬于表格上方 | 单元格 mousedown 触发 11805-11809；`buildObjbar('tbl')` 13006-13009；`selectTblFrame` 10438-10442 |
| **块菜单 blkmenu**（悬浮菜单） | 悬停左缘 ⠿ 手柄点击 / Ctrl+/ | 表格标注（v3.31.3 TBL-3 移入）、删除块、还原尺寸、复制块、上移、下移 | 9617-9625 |
| **右键菜单 tblbar**（表格工具栏） | 单元格右键 | 行插入/删除、列插入/删除、合并/拆分、移动四向、对齐三向、清空内容（上下文动态过滤，不可用项整组隐藏） | 11700-11752 |
| （隐含）单元格内 `/` 菜单 | 单元格内键入 `/` | 仅显示单元格支持的 5 类：列表 / 代码块 / 图片 / 图表 / 公式（`CELL_SLASH_IDS`） | 7745、8529 过滤 |

**历史脉络（理解现状的关键）**：

1. **v3.30.17**：「标注」从右键菜单迁出（11751 注释），做成表格悬浮工具按钮（objbar）——当时的动机是右键菜单「聚焦表格结构操作」，而 objbar 是标注的唯一悬浮入口；
2. **v3.31.3（TBL-3）**：「表格标注」又补进了块菜单（9618-9619）——从此 objbar 与 blkmenu 形成**双入口重复**，objbar 的表格分支退化为纯冗余；
3. **v3.30.10**：单元格内块级插入做成**有意的三通道**——`/` 菜单、格式栏「＋」、快捷键 Ctrl+Shift+K/M（7736-7744 注释自述）；
4. **v3.36（TPL-E）**：「插入模板」按钮从格式栏移除，确立了**「行内格式栏专注行内格式」**的收敛原则（7396-7397 注释自述）——但「＋」作为另一处同类异层残留未一并处理。

## 二、原始设计预期逐条对照

| 设计预期 | 达成情况 | 证据 |
|---|---|---|
| ① 选中单元格文字后，格式化操作以悬浮命令呈现，与通用格式化一致 | ✅ **已达成** | 格式栏在单元格内外是同一套按钮（7382-7390），单元格内选区走 `applyCellFloat` 按表格类型改写该格源码（管道表加 `**` / HTML 表加 `<strong>`，7882-7886），v3.37 起单元格同样支持下划线（7632） |
| ② 表格右键菜单聚焦表格相关操作 | ✅ **已达成** | tblbar 全部条目均为结构操作（行列 / 合并拆分 / 移动 / 对齐 / 清空），无行内格式项、无块级项；标注已迁出 |
| ③ 悬浮菜单整合其他悬浮菜单的通用操作（表格标注、删除块、还原尺寸等） | ✅ **已达成，但有残留** | blkmenu 表格分支已集齐三项（9617-9625）；**残留**：objbar 的「标注」（重复入口）与格式栏的「＋」（未纳入整合）未随之清理 |

**总体判断**：三者的职责框架与设计预期一致，当前问题不是「缺设计」，而是**两轮迭代留下的入口残留未回收**——每一轮新入口上线时都合理，但旧入口没有同步下线。

## 三、三个具体问题的回答

### Q1 ｜ 单元格选中时出现的「标注」悬浮命令，是否应删除？

**结论：应删除（objbar 表格分支整体下线）。**

理由：

1. **功能 100% 重复**：objbar「标注」（13008）与 blkmenu「表格标注」（9619）调用同一个 `openTblCaption(idx)`，用户感知不到任何差异，只会困惑「为什么有两个一样的入口」；
2. **单按钮工具条价值极低**：objbar 表格分支只剩标注一项（图片 v3.30.17 起已不用 objbar、收进右键菜单，13011 注释），为一个小按钮维持一整套「弹出—定位—拖选隐藏/再现—滚动收起」的浮层生命周期（11805-11812），成本收益倒挂；
3. **高频动作伴随低频按钮 = 视觉噪声**：点击单元格是表格编辑中最高频的动作（定位光标、编辑文字），而标注是全表生命周期内最多设置一两次的低频操作——每次点单元格都在表格上方闪现一个用不到的按钮，注意力成本持续支付；
4. **与设计预期③冲突**：通用块级操作的整合者已明确是 blkmenu；
5. **历史包袱说**：objbar 是 v3.30.17 的过渡产物（当时 blkmenu 还没有标注），TBL-3 落地后它的历史使命已经完成。

**弊与缓解**：删除后失去「点击即见」的发现途径——这恰好是 Q3 要补的洞，用可发现性改善统一补偿，而不是靠重复入口硬扛。删除后 objbar 仅保留图表（mmd）分支（图注/重置尺寸/源码/删除，13013-13019），其「高频源码编辑」符合单钮条形态。

**实施锚点**：`selectTblFrame`（10440-10442）与单元格 mousedown（11807-11809）两处 `buildObjbar('tbl')` 调用 + `buildObjbar` 的 `kind === 'tbl'` 分支（13006-13009）。

### Q2 ｜ 格式栏的「＋」（插入图表等）是否应统一放入悬浮菜单？

**结论：应从格式栏移除，但建议「移除 + 补位」而不是简单删掉。**

先厘清事实：「＋」当前与**块菜单无关**——它是 v3.30.10 三通道设计（`/` 菜单、格式栏＋、快捷键）之一，弹出的是 `openCellInsertMenu`（7863），与单元格内 `/` 菜单共用同一份 `CELL_SLASH_IDS`（列表/代码块/图片/图表/公式），**项目完全相同**。所以真实问题是：**同一个插入菜单在表格内有两个等价入口，一个在行内格式栏、一个在键盘流**。

建议移除的理由：

1. **层级错位**：「＋」弹出的是**块级插入**（往单元格里塞列表/图表），却挂在**行内格式栏**上——行内层混入块级操作，与 v3.36 TPL-E「行内格式栏专注行内格式」的既定收敛方向直接矛盾（模板按钮就是同类问题被移除的）；
2. **冗余通道**：`/` 菜单同项可用且更快（手不离键盘），快捷键覆盖高频两类（代码块/公式）；
3. **按钮位拥挤**：格式栏 8 个行内按钮 + 尾部字数，单元格内再加「＋」，小选区时浮条过宽。

**但必须正视「＋」的合理内核——可发现性**：`/` 是隐藏知识（用户得被告知才知道），「＋」是可见入口。直接删除会加重 Q3 的洞。因此建议**配套补位**：

- **首选**：空单元格占位符提示「输入 / 插入列表、图片、图表」——单元格已有 `data-ph` 占位机制（脚注 `fnedit`、定义列表 `dd` 均在用），扩展成本低，且把发现时机放在用户最需要的那一刻；
- **保守替代**（若不想动占位符）：「＋」保留但仅在**空单元格**显示——有内容的单元格说明用户在写文字而非插块，此时格式栏回归纯行内；
- 不建议放进 blkmenu：插入的目标是「光标所在格」，blkmenu 的锚是「整块」，对象粒度不匹配，且 blkmenu 不该越长越长（Q3 的负担会更重）。

### Q3 ｜ 悬浮菜单（blkmenu）是否存在可发现性缺陷？

**结论：存在，且是这套浮层体系当前的主要体验矛盾。**

**表现与原因**：

1. **入口物理隐蔽**：⠿ 手柄仅在块悬停时出现（v3.30.9 报告实测：块悬停触发、移出 16px 吸附区即消失）——不悬停就永远看不见，而「悬停左缘」本身是一个需要被告知的动作；
2. **表格场景距离放大**：用户操作视线在单元格上，手柄在表格块左缘——宽表格下两者相距数百像素；表格横向可滚动时手柄甚至可能不在视口内；
3. **无界面提示的快捷键**：Ctrl+/ 无任何 UI 露出，命令面板之外无从得知；
4. **菜单能力无视觉边界反馈**：引用块测试（BQ-1）已实证 `markBlockMenuBoundary` 边界置灰是死代码——哪些块有什么菜单能力，用户只能试出来；
5. **系统性佐证**：《产品评审与优化清单 v3.31》P1-4 已把「功能可发现性依赖用户自己找」列为必须补齐项，blkmenu 正是典型样本。

**影响**：blkmenu 承担的整合职责（标注/还原尺寸/复制块/上下移）实际触达率低 → 用户误判「功能不存在」。**值得注意的因果**：v3.30.17 先做 objbar「标注」悬浮按钮、v3.31.3 才补 TBL-3，很可能正是因为开发者自己感知到了 blkmenu 触达难，用 objbar 打补丁——但补丁与整合目标冲突，形成 Q1 的重复。**结论：Q1/Q2 的收敛必须与 Q3 的可发现性改善捆绑推进，否则删掉的入口就真的找不回来了。**

**改善建议（按性价比排序）**：

1. **命令面板收录块级动作**（最低成本）：「表格标注 / 还原尺寸 / 复制块」进命令面板，先保证「想得起就搜得到」；
2. **特殊块选中时手柄脉冲提示**：点击表格/图片/图表时，对应块手柄短暂高亮一次 + tooltip「块菜单（Ctrl+/）」——把 objbar 的「点击即见」优点以更轻的方式继承过来；
3. **手柄 hover 常显化评估**：特殊块（表格/图片/图表/公式/代码块）的手柄在块悬停时常显（普通文本块维持现状），缩小「不知道有菜单」的人群；
4. 文档与欢迎页提及（P1-3 上手引导顺带覆盖）。

## 四、三者功能划分方案（按对象层级 × 操作频率）

| 层级 | 交互面 | 职责边界 | 判据 | 动作 |
|---|---|---|---|---|
| **行内层**（选中文字） | 格式栏 floatbar | 纯行内格式，表格内外同一套（单元格走 `applyCellFloat` 映射） | 与通用一致（设计预期①） | **移除「＋」**（Q2） |
| **结构层**（单元格/选区形状） | 右键菜单 tblbar | 行列 / 合并拆分 / 移动 / 对齐 / 清空——全部依赖选区形状的结构操作 | 聚焦表格操作（设计预期②） | **保持现状** |
| **块级层**（整表生命周期） | 块菜单 blkmenu | 标注 / 删除块 / 还原尺寸 / 复制块 / 上移下移 | 整合通用操作（设计预期③） | **保持并做主入口**，补可发现性（Q3） |
| **对象预览层**（媒体对象） | objbar | 仅保留图表（源码编辑为高频单动作） | 高频 + 单动作 + 即点即得 | **删除表格分支**（Q1） |

一句话原则：**选中什么，浮层就只谈什么层面的事**——选文字谈格式，选格子谈结构，选块谈生命周期；同一动作只在一个层级有一个入口。

## 五、是否需要把悬浮菜单中的常见操作独立为悬浮命令形式？

**结论：不需要；方向应当相反——继续向菜单收敛，把省下的浮层预算花在可发现性上。**

判断标准（什么时候值得独立为悬浮命令/单钮条）：

| 维度 | 适合独立悬浮命令 | 表格块级操作的实际画像 |
|---|---|---|
| 频率 | 高频（每次选中都会用） | 低频：标注全表一次、还原尺寸偶发、删除/移动偶发 |
| 动作数 | 单动作即点即得 | 集合型（≥5 项） |
| 对象 | 自身就是操作目标（如图表→源码） | 目标是格子里的文字，块级操作是背景需求 |
| 空间 | 悬浮位不遮挡内容 | 表格上方正是表头/标题区，常驻按钮必然遮挡 |

**利弊权衡**：

- 独立化的**利**：触达快一步、可发现性好（「＋」和 objbar 的存在价值即在于此）；
- 独立化的**弊**：浮层数量与视觉噪声上升（Q1 已实证：每次点单元格弹一个用不到的按钮）；同一功能双入口的认知与测试成本翻倍；与既定的整合方向（TBL-3、TPL-E 两次收敛）背道而驰；
- **本表格场景下弊 > 利**：低频集合型操作独立化，等于把菜单的整齐换成浮层的嘈杂；
- **反例保留**：图表 mmd 的 objbar（源码/删除）符合「高频单动作」标准，继续保留——这正好校准了边界：objbar 不是要废除，而是只留给真正高频的对象操作。

## 七、遗留观察

- objbar 删除表格分支后，`selectTblFrame` 内 `showRzFrame`（整表缩放框）保留——缩放是表格的高频直接操纵，与本次结论不冲突；
- 若未来单元格内插入类型扩充（如脚注），`CELL_SLASH_IDS` 单一来源（7745）保证 `/` 菜单与占位提示文案可共用一份清单，不会再度分叉；
- 本分析未覆盖触屏/高 DPI 下的浮层表现（v3.30.9 报告遗留项 ③），若移动端适配立项需补测。
