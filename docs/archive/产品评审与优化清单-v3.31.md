## 1. 产品现状速描（评审基线）

**一句话**：本地、免费、真 Markdown 保真的中文块级 WYSIWYG 编辑器；能力面已超 Typora（表格合并/网格、图表就地编辑、脚注/定义列表、版本历史 diff、树形目录、懒渲染）。

**已具备的产品骨架（12 模块）**：文档管理（多标签/自动保存/版本历史+diff）· 编辑内核（三视图/斜杠菜单/命令面板/懒渲染）· 表格 · 公式与图表 · 图片管理（assets 落盘/内嵌双模式）· 查找与全局搜索 · 导航与大纲（拖拽调序/分节字数）· 文件目录树 · 导出（HTML/PDF 书签/Word/EPUB/pandoc）· 主题 · 设置与帮助 · 启动与集成。

**实证核查结果（本次新增）**：

| 核查项 | 结论 | 证据 |
|---|---|---|
| 数据埋点 / 遥测 | ❌ **完全没有**（无 telemetry/analytics/统计上报代码） | `src/` 全目录 grep 无命中 |
| 商业化（授权/激活/试用/捐赠） | ❌ **完全没有** | grep 仅命中第三方库 MIT 文本 |
| 自动更新 / 版本检查 | ❌ **无** | grep check_update 无命中 |

## 2. P0｜必须补齐的基础问题（阻断级，建议 v3.32 内全部闭环）

> 共性：**都会造成"用户资产损失"或"用户无法完成核心任务"**，且成本大多不高。属于**必须补齐**，而非加分项。

### P0-1 ｜ 未命名新建文档零保护，进程崩溃即全文丢失
- **维度**：异常与边界 ｜ **成本**：低 ｜ **类型**：必须补齐（数据安全底线）
- **问题/风险** → 自动保存仅在文档"已有路径"时生效（功能列表 §3-A 明示"未命名文档不会自动落盘"），且全应用**无草稿/崩溃恢复机制**。用户 Ctrl+N 写 3000 字 → 程序崩溃 / 断电 / 系统更新重启 → **内容 100% 丢失**，仅有的保护是"关闭时询问是否保存"（`mainwindow.py:1656`），且该保护对崩溃完全无效。
- **影响范围** → 全部新用户首触流程；长文写作者；任何非正常退出场景。这是**唯一会造成不可逆内容损失的产品级缺口**（工程清单里的 QUO-1 类问题已修复，本项是同类风险的最后一块空白）。
- **优化建议** → ① 新建文档即在 `%APPDATA%/mdEditor/drafts/` 建立影子草稿（10s 节流写入，内容非空才写）；② 启动时检测到孤儿草稿 → 弹「发现未恢复内容，是否恢复？」并展示前 200 字与时间戳；③ 未命名标签显示"未保存"徽标，状态栏给出"草稿已自动暂存"的正向反馈。
- **预期收益** → 消灭最高级别的数据丢失投诉；新用户首触不再有"写半天没了"的负向记忆；为后续"写作连续性"留存设计打底。
- **竞品参考** → **VSCode 的 Hot Exit**（退出/崩溃后未保存文件原样恢复，是编辑器品类的默认预期）；**Typora** 亦提供未保存文件恢复。这是"编辑器品类及格线"，不是加分项。

### P0-2 ｜ 无单实例互斥，同一文档双开会静默互相覆盖
- **维度**：异常与边界 ｜ **成本**：低 ｜ **类型**：必须补齐
- **问题/风险** → 无 `QLocalServer` 单实例机制，双击两次即可开两个进程；配合"自动保存 700ms 轮询 + 有路径即写盘"，两个窗口打开同一 `.md` 时**后写盘的一方静默覆盖另一方**，用户不会收到任何冲突提示（版本历史只保留"写盘前快照"，覆盖一旦发生，另一窗口的内容只能靠历史快照找回，且用户不知道要去找）。
- **影响范围** → 所有通过双击/拖拽打开文档的用户；多窗口工作者；与"用外部编辑器打开"联动时风险翻倍。
- **优化建议** → ① 启动用 QLocalServer 抢占，第二个实例把命令行参数转发给首个实例后退出（新开标签页）；② 兜底：打开文件前检测该路径是否已被本进程其它标签占用，是则提示并聚焦已有标签；③ 进阶（P2）：外部修改导致磁盘内容变化时提示"文件已被外部修改，重新载入？"。
- **预期收益** → 消除一类"无声数据覆盖"；顺带把"命令行/拖拽打开"体验做顺（现在是开新进程，慢且割裂）。
- **竞品参考** → **Typora / VSCode** 均为单实例多窗口模型，二次启动把文件交给已有实例；**Obsidian** 更进一步，Vault 级独占。

### P0-3 ｜ 版本历史的覆盖条件不确定，用户以为有保护其实可能没有
- **维度**：核心流程闭环 ｜ **成本**：低 ｜ **类型**：必须补齐
- **问题/风险** → 快照挂载在"自动保存写盘"路径上（60 秒节流），**手动 Ctrl+S 是否触发快照尚未确认**（`功能列表 §7 待确认项 2`）。若用户关闭自动保存（设置可关）或习惯手动保存，则**版本历史可能是空的**——而用户从功能介绍里读到的是"有版本历史"，形成安全错觉。此外历史仅对"已保存过的文档"生效，与 P0-1 的未命名文档形成保护真空。
- **影响范围** → 关闭自动保存的用户、手动保存习惯用户、论文与长篇项目文档等长周期写作场景。
- **优化建议** → ① 手动保存同样触发快照（与自动保存共用节流）；② 历史对话框顶部显示"保留策略与触发规则"一行说明，空列表时明确告知原因（如"本文档尚未产生快照／自动保存已关闭"）；③ 增加"立即留档"命令（命令面板 + Ctrl+Shift+H 内按钮），让用户可主动打点。
- **预期收益** → 把"看起来有保护"变成"确实有保护"；降低误删/误改后的求助量。
- **竞品参考** → **Obsidian 的 File Recovery / Version history**：时间轴式快照 + 明确的保留时长说明，并允许手动打点；**Joplin** 的笔记历史同样提供"恢复"与保留期配置。

### P0-4 ｜ 导出交付的最后一公里未闭环（块级公式降级 + Mermaid 离线口径冲突）
- **维度**：核心流程闭环 ｜ **成本**：中 ｜ **类型**：必须补齐
- **问题/风险** → 导出是 mdEditor 的核心价值出口（论文/报告/资料交付），但存在两处硬伤：① **块级公式导出 Word/EPUB 仅留 LaTeX 源码**（MATH-2 明确未实现），学术交付场景直接不可用；② **Mermaid 图表导出后是否离线可用，三份文档口径互相矛盾**——`README.md` 写"图表经 CDN 渲染"，`功能列表 §3-I` 写"Mermaid 需要查看端联网…注意"，而 BUG 清单记载 MMD-3（导出静态内嵌 SVG）已落地。口径不一是产品发布的红线。
- **影响范围** → 所有需要"发出去给别人看"的用户；学术写作与报告交付场景（恰恰是 A1 假设中的核心人群）。
- **优化建议** → ① 先做一次**断网实测**：导出含图表的 HTML，拔网打开，结论写进功能列表与 README（成本极低，先止血）；② 公式图片化链路专项排期（KaTeX→SVG/PNG 内嵌；OMML 作远期）；③ 导出前增加"交付自检"：扫描文档中的图表/公式/远程图片，提示"本文档含 N 处需联网或会降级的元素"，让用户**在导出前知道会发生什么**。
- **预期收益** → 把"导出→交付"这条主流程真正闭环；消除"交付出去发现图没了/公式是源码"的信任事故。
- **竞品参考** → **Typora** 导出 HTML 默认自包含（图片内嵌、公式/图表渲染结果一并打包），是"发出去就能看"的标杆；**Pandoc** 的 `--self-contained` 也是这一理念的体现。

### P0-5 ｜ 无任何日志与诊断出口，用户遇问题只能描述，产品侧拿不到证据
- **维度**：异常与边界 ｜ **成本**：低 ｜ **类型**：必须补齐
- **问题/风险** → 桌面应用必然出现环境差异（pandoc 路径、字体、编码、Python 依赖缺失、WebEngine 渲染差异）。当前无日志落盘、无"导出诊断信息"入口，用户报错只能说"导出失败"，产品侧无法定位，只能来回追问——这在有真实用户后是最昂贵的成本。
- **影响范围** → 全部导出链路（依赖 pandoc / python-docx / pypdf）、编码兼容、所有环境相关故障。
- **优化建议** → ① 本地滚动日志 `%APPDATA%/mdEditor/logs/`（默认 INFO，可开关 DEBUG）；② 设置页「关于」增加**「复制诊断信息」**（版本 / 系统 / 主题 / 依赖检测结果 / 最近 50 行日志）；③ 导出失败的错误提示改为"原因 + 修复指引"（如"未找到 pandoc，已使用内置导出；点击配置路径"），而不是笼统失败。
- **预期收益** → 故障定位时间从"来回追问"降到"一次拿到信息"；为 P1-5 的埋点做基础设施。
- **竞品参考** → **Joplin** 的"导出诊断报告 / Log"是桌面笔记工具的标配；**VSCode** 的"导出诊断 + 问题面板"同理。

### P0-6 ｜ 分发与升级断链：217MB zip、无安装器/签名/更新检查，装完即失联
- **维度**：商业化与留存 ｜ **成本**：中（安装器+签名=高，可分期） ｜ **类型**：必须补齐
- **问题/风险** → 分发物是 217MB 的 `mdEditor-v3.20-win64.zip`（且版本号落后于 v3.31），无安装程序、无数字签名（Windows SmartScreen 大概率拦截）、无版本检查。结果是：**获客成本高（信任门槛）、版本陈旧无法召回、用户装了旧版却在旧版上形成口碑**。当前 v3.12→v3.31 仅用 9 天迭代，但分发物停在 v3.20 —— **研发产出没有传导到用户端**，这是最大的隐性浪费。
- **影响范围** → 100% 的新用户获取与老用户升级路径。
- **优化建议** → 分三步：① **低成本先做**：每次发版同步更新分发包 + 提供 `version.json` 与「帮助 → 检查更新」（只提示、不强升，跳转下载页）；② **中期**：NSIS/Inno Setup 安装包 + 开始菜单/卸载项 + 文件关联 `.md`（双击 md 直接用 mdEditor 打开，是高频留存钩子）；③ **长期**：代码签名证书（消除 SmartScreen）。
- **预期收益** → 新版本触达率从"靠手动传包"变为可运营；`.md` 文件关联是低成本的日活抓手；安装包显著抬升首次信任。
- **竞品参考** → **Typora / Obsidian / Joplin** 均提供官方安装器 + 应用内更新通道；**Joplin** 桌面端默认启动时检查新版本并提示。

### P0-7 ｜ 本地唯一副本，无备份与容灾引导
- **维度**：异常与边界 ｜ **成本**：中 ｜ **类型**：必须补齐
- **问题/风险** → 产品定位"本地优先"本身没问题，但**"本地"意味着用户的全部资产押在一块硬盘上**，而产品没有任何备份提示或归档出口。一旦磁盘故障/误删 `.mdeditor-history` 与文档目录，用户多年笔记归零，且会归咎于工具。
- **影响范围** → 全部长期用户；论文与长文资料等不可逆资产场景。
- **优化建议** → ① 轻量版（低成本）：「文件 → 归档整个工作区…」导出带时间戳的 zip（含 assets + history 可选），并在首次使用满 30 天/文档数达 20 时给一次温和提醒；② 进阶（P2）：定时备份到指定目录 / WebDAV / 网盘同步文件夹；③ 与 P1-6 的增值服务（云同步）天然衔接——**先用"手动归档"验证需求，再决定是否做付费同步**。
- **预期收益** → 把"数据自主"从口号变成可执行的保障；为付费同步铺需求验证路径。
- **竞品参考** → **Obsidian** 用 Sync 付费解决，但**Joplin** 提供更轻的 WebDAV/Dropbox/OneDrive 通道 + 端到端加密（更适合本地优先用户的心理模型）；**思源笔记**支持 S3/WebDAV 与"数据快照"导出。

## 3. P1｜影响留存与口碑的关键项（建议 v3.32~v3.34 分批）

### P1-1 ｜ 通用能力未沉淀为场景模板，用户每次都从空白页起步
- **维度**：目标用户与核心需求匹配 ｜ **成本**：中 ｜ **类型**：必须补齐（若认可 A1 假设）
- **问题/风险** → 块级编辑、表格、公式图表、脚注、导出等能力都已具备，但**没有任何开箱即用的场景模板**：写技术笔记、项目文档、周报、评审记录、论文骨架时，用户每次都要从空白页重新搭结构、重新调格式。结果是能力很强、启动很慢——用户感知停留在"又一个编辑器"，而不是"拿来就能写"。
- **影响范围** → 全体用户的高频重复写作场景（技术笔记 / 项目文档 / 周报 / 评审记录 / 论文骨架）；长文与新用户的起步成本最高。
- **优化建议** → 做**内置最小模板集**而非大功能：① 斜杠菜单新增「模板」一级项，内置 5~8 个模板（技术笔记、项目文档、周报、评审记录、论文骨架、会议纪要），插入即用，模板内容全部为纯 Markdown（不引入私有语法）；② 模板与已有点能力组合（表格/图注/脚注/导出预设）而非另起炉灶；③ 用户自定义与模板管理放在 P2-1 迭代。
- **预期收益** → 降低写作启动成本，提升"首日完成一篇文档"的比例；让已有的块级能力被成体系地感知到，是最短的体验差异化路径。
- **竞品参考** → **Obsidian** 的 Templates 核心插件 / Templater（模板即场景，插入即用）；**Notion** 的 Template Gallery（把块能力打包成开箱即用的场景）；**VSCode** 的 User Snippets（降低重复结构的录入成本）。

### P1-2 ｜ 核心流程断点：写作 → 交付 → 发布，最后一环缺失
- **维度**：核心流程闭环 ｜ **成本**：中 ｜ **类型**：必须补齐
- **问题/风险** → 用户写作的最终目的通常是"给别人看"（发博客、发公众号、交付报告、分享 PDF）。目前到"导出文件"就结束了：**无一键发布、无分享链接、无"导出后打开/定位"的收尾动作**；已有的「复制为 HTML」（公众号场景刚需）埋在菜单里，可发现性弱。用户拿到文件后的下一步，产品不再参与——**价值链条在最接近传播的地方断掉**。
- **影响范围** → 全部有分享需求的用户；产品自传播能力。
- **优化建议** → ① 导出完成弹窗加"打开所在文件夹 / 打开该文件"收尾动作（`<1` 人日，立刻可做）；② 把「复制为 HTML（公众号/Word 富文本）」提到文件菜单一级 + 命令面板高权重，并在导出对话框并列展示；③ 中期：导出 HTML 时可选"生成自包含分享页"，用户自行托管；④ 长期（P2）：官方发布通道（与 P1-6 商业化绑定）。
- **预期收益** → 提升导出后的正向完成感；"复制为富文本"是中文用户最高频的交付动作，提到台前后使用量与口碑都会涨。
- **竞品参考** → **Notion** 的 Share link（一键即完成"给别人看"）；**语雀/飞书文档**的"分享"与"导出"并列；**Typora** 导出后有系统级的文件定位反馈。

### P1-3 ｜ 首次启动与空状态：有欢迎页，但没有"教会用户"
- **维度**：交互与信息架构 ｜ **成本**：低 ｜ **类型**：必须补齐
- **问题/风险** → 首启仅有静态欢迎文档（`# 欢迎使用 mdEditor` + 一句说明）。新用户不知道三件事：**这个编辑器比 Typora 强在哪（表格/图表/公式）**、**斜杠菜单这个核心入口**、**图片与导出的正确姿势**。而这些恰恰是留存关键——用户在头 10 分钟没感受到差异，就会退回旧工具。
- **影响范围** → 全部新用户；尤其是从 Typora/有道云迁移来的用户。
- **优化建议** → ① 欢迎页改造成「3 分钟上手」交互清单：输入 `/` 试试 → 插入一张图 → 导出一次 PDF（完成打勾，可跳过）；② 空状态文案化：空大纲页提示"输入 `# 标题` 开始"、空搜索结果给"换个关键词/试试正则"、目录树空目录已有占位（保持）；③ 帮助菜单增加「使用手册」入口（先用一份内置 `.md`，成本最低）。
- **预期收益** → 提升首日激活率（完成一次完整流程的用户比例），这是留存的最强单点。
- **竞品参考** → **Obsidian 的 Help Vault**（内置示例库 + 可执行教程文档，是公认最好的桌面笔记 onboarding）；**Notion** 的 Getting Started 模板与引导清单。

### P1-4 ｜ 功能可发现性依赖"用户自己找"，强能力藏在深处
- **维度**：交互与信息架构 ｜ **成本**：低 ｜ **类型**：必须补齐
- **问题/风险** → 侧栏 4 页（文件列表/大纲/目录树/搜索）+ 三页设置 + 命令面板 + 快捷键自定义，信息量已经不小。**越强大的功能越依赖用户知道它存在**：合并单元格、脚注重排、命令面板拼音匹配、正则速查、版本 diff……目前只有 F1 一览与 CHANGELOG 两个出口，新用户几乎不可能自然发现。
- **影响范围** → 全体用户的功能使用率；口碑传播时的"卖点能否被说出来"。
- **优化建议** → ① 命令面板增加"推荐/新手"分组，启动时按使用次数排序（本地计数即可，不需上传）；② 首月展示「每日一提示」（Tip of the day，可关闭，内容来自功能列表，成本极低）；③ 设置页加搜索框（#22 已在清单中，成本很低）。
- **预期收益** → 让已投入开发的功能被真正用起来，提升"功能感知价值/开发成本"的比值（性价比最高的一类优化）。
- **竞品参考** → **VSCode** 的 "Tip / Walkthrough" 与命令面板最近使用排序；**Notion** 的模板与引导入口前置。

### P1-5 ｜ 数据埋点完全缺失 —— 产品只能凭感觉决策
- **维度**：数据与增长埋点 ｜ **成本**：中 ｜ **类型**：必须补齐（若认可 A3）
- **问题/风险** → 零遥测、零本地统计。直接后果：**不知道日活多少、不知道导出成功率、不知道哪些功能是摆设、不知道用户在哪一步流失**。上面所有优先级排序目前都只能靠假设（包括我的 A1~A5）。对本地工具而言，这是"闭眼开车"。
- **影响范围** → 全部产品决策；P1-1/P1-6（场景与商业化）尤其依赖数据验证。
- **优化建议** → **隐私优先三步走**（本地工具用户对遥测极度敏感，必须显式 opt-in）：
  ① **先做纯本地用量统计**（不上网，无争议）：启动次数、活跃天数、文档数、各功能使用计数、导出类型与成功/失败——存本地 SQLite，设置页可视化"你的使用报告"，本身就是一个留存钩子；
  ② **再做匿名遥测 opt-in**：首次启动时明确询问（默认关闭），只上报聚合事件，不含任何文档内容/路径/文件名，并提供一键关闭；
  ③ **崩溃与错误上报单独开关**（与 P0-5 日志共用通道）。
  **最小事件集**：app_start / app_active_day / doc_create / doc_save / export_{type}_{success|fail} / feature_use{slash_menu, table_merge, math, mermaid, footnote, find_all, outline_drag, history_diff} / crash。
- **预期收益** → 从"凭感觉排期"转为"按使用数据排期"；`feature_use` 能直接砍掉伪需求功能、加大真需求投入。
- **竞品参考** → **VSCode** 的遥测 opt-in + 分级（默认可关、公开事件字典）；**Obsidian** 默认零遥测，仅在付费服务侧有账户数据——证明"本地工具不埋点也能活，但要做商业化就必须有数据"。

### P1-6 ｜ 商业化路径未定义 —— 免费是获客优势，但没有变现出口
- **维度**：商业化与留存 ｜ **成本**：高（涉及服务端） ｜ **类型**：必须补齐（战略层）
- **问题/风险** → 完全免费、无账号、无付费点。短期是获客利器（对打 Typora ¥89），长期是**不可持续**：服务器/签名证书/持续迭代都需要成本，且无账号意味着**无用户关系、无召回能力**。
- **影响范围** → 产品可持续性；能否招人/能否持续投入。
- **优化建议** → 采用 **Obsidian 模式**（软件免费 + 服务收费），分三步验证：
  ① **零成本先验证意愿**：关于页加"赞助/请喝咖啡"入口（不指望收入，看意愿信号）；
  ② **轻量增值**：场景模板包（技术文档 / 项目报告 / 周报 / 论文骨架）、主题包——纯内容交付，无服务端；
  ③ **服务端增值**：云同步（多设备）、一键发布分享页（P1-2 的进阶版）、AI 校对润色。
  **明确保守住的底线**：编辑器本体永久免费、真 `.md` 保真、不强制账号——这是差异化根基，一旦破坏，P1-1/P2 的差异化全部失效。
- **预期收益** → 建立可持续模型；账号体系反过来补齐留存与召回能力。
- **竞品参考** → **Obsidian**：软件免费，Sync（同步）与 Publish（发布）按月订阅，是被验证过的"本地优先工具"最优商业模式；**Joplin**：官方云同步收费 + 支持自建 WebDAV；**Typora**：¥89 买断（反例：付费门槛正是 mdEditor 的获客机会）。

### P1-7 ｜ 留存设计缺失：用户没有"回来"的理由
- **维度**：商业化与留存 ｜ **成本**：中 ｜ **类型**：必须补齐
- **问题/风险** → 没有账号、没有目标、没有提醒、没有统计反馈。用户写完一篇就走，**工具型产品天然低频**，缺少回访钩子会让 DAU 极度依赖"刚好要写东西"。
- **影响范围** → 次周/次月留存；长期用户资产积累。
- **优化建议** → 三条无需账号即可做的留存：① **写作目标与统计**（每日字数目标 + 进度反馈，见 P2-2 可提级）；② **本地周报**：每周首次启动时展示"本周写了 X 字 / Y 篇 / 最长一篇"（纯本地计算，成本中）；③ **连续写作天数**（写作日历热力图），把"坚持"变成可见资产。
- **预期收益** → 把"工具"变成"习惯载体"，直接抬升 WAD（北极星指标）。
- **竞品参考** → **Ulysses** 的写作目标与统计环（把写作变成游戏化坚持）；**Obsidian** 的 Daily Note + 日历热力图插件生态；**多邻国式连续天数**心理机制（通用设计范式）。

### P1-8 ｜ 用户反馈与社区闭环缺失
- **维度**：商业化与留存 ｜ **成本**：低 ｜ **类型**：必须补齐
- **问题/风险** → 无反馈入口、无社区、无更新公告渠道。用户遇到问题只会静默流失；而早期用户恰恰是最佳的产品顾问。
- **影响范围** → 口碑传播、需求来源、问题解决率。
- **优化建议** → ① 帮助菜单「反馈与建议」（mailto / 表单链接 / 社群二维码）；② 关于页「检查更新」与「更新日志」入口（CHANGELOG 已有 46KB，直接复用）；③ 建立 QQ/微信群或 GitHub Issues，把反馈沉淀为需求池。
- **预期收益** → 低成本获取真实需求；把流失用户变成共创用户。
- **竞品参考** → **Joplin / Obsidian** 均有公开社区与 Issue 驱动的路线图；**Typora** 的反馈邮箱 + 论坛。

### P1-9 ｜ 性能与容量边界对用户"静默"，超出即卡死
- **维度**：异常与边界 ｜ **成本**：低 ｜ **类型**：必须补齐
- **问题/风险** → 全局搜索有 1500 文件/1.5MB/400 命中上限，懒渲染阈值 400 块，图片 >1MB 内嵌提示，超长文档/超大图片会导致卡顿——**这些边界在产品内没有向用户明示**，用户遇到的是"莫名其妙变慢/搜不到"，而不是"我触发了限制"。
- **影响范围** → 大型知识库用户、图片密集型文档作者。
- **优化建议** → ① 触发上限时在结果区明确提示"已达上限（1500 文件），请缩小目录范围"；② 超 400 块文档首次进入时 toast 提示"已启用长文档优化"；③ 大图插入给出压缩建议（可选降采样）。
- **预期收益** → 把"卡顿"从 bug 观感变成"受控的设计选择"，避免差评。
- **竞品参考** → **VSCode** 对大文件给出明确的"文件过大，已禁用某些功能"提示；**Notion** 对超限集合给出"已截断"说明。

### P1-10 ｜ 导出结果无预览，"所见"与"所得"的落差不可预期
- **维度**：核心流程闭环 ｜ **成本**：中 ｜ **类型**：必须补齐
- **问题/风险** → 导出 PDF/Word 前无法预览结果；用户只能导出→打开→发现版式不对→回来改→再导出，形成低效循环；且 Word 侧有明确降级项（行内公式转文本、块级公式仅源码）。
- **影响范围** → 需要交付 Word/PDF 的用户（A1 假设中的核心人群）。
- **优化建议** → ① 导出对话框增加"降级项清单"提示（本文档含 N 处行内公式将转为纯文本 / M 处图表将以位图嵌入 / 图片已内嵌）；② 优先补 PDF 预览（Qt 已有打印能力，成本相对低）；③ Word 预览依赖外部程序，改为"导出后自动打开"更实际。
- **预期收益** → 把"反复试错"变成"一次成功"，显著提升交付满意度。
- **竞品参考** → **Typora** 的导出即 WYSIWYG 一致性（其最大口碑来源）；**Pandoc** 在转换时对不支持元素的显式 warning 机制。

## 5. 必须补齐 vs 差异化加分项（明确切分）

### 5.1 必须补齐的基础问题（不做 = 产品不及格 / 有资产风险）
> 判断标准：**会造成用户内容损失、核心流程走不通、或让用户无法自助**。这些是"及格线"，不是竞争力。

- **数据安全**：P0-1 未命名文档零保护、P0-2 无单实例覆盖、P0-3 版本历史覆盖不确定、P0-7 无备份引导
- **交付可信**：P0-4 导出最后一公里、P1-10 导出无预览/无降级提示
- **可运维**：P0-5 无日志诊断、P1-9 边界静默
- **可触达**：P0-6 分发与升级断链、P1-8 反馈闭环
- **可决策**：P1-5 数据埋点、P1-3/P1-4 上手引导与可发现性
- **可存续**：P1-6 商业化路径、P1-7 留存设计

### 5.2 差异化加分项（做了 = 有理由被选择 / 被传播 / 被付费）
> 判断标准：**竞品没有，或竞品收费而我们免费**。这类项应围绕已确立的定位做深，而不是盲目扩功能。

| 加分项 | 差异化理由（竞品对照） | 建议节奏 |
|---|---|---|
| **表格能力标杆**（合并/拆分/网格/表头保护/右键只显示可执行项） | **Typora 表格能力明显更弱**，Obsidian 原生表格也弱（需付费/插件增强）——这是当前最硬的差异化 | **先做对外物料**：README/官网放功能对比表（成本最低、转化最高） |
| **中文写作细节** | 中英文分计字数、图注、脚注/定义列表、中文 IME 兼容、中文标点处理——**Typora/VSCode 均无针对中文的优化** | 持续做深，作为品牌标签 |
| **真 `.md` 保真 + 本地免费** | 对打 Typora ¥89 买断、Notion 私有格式——**必须写进对外承诺并永远守住** | 定位层，不可动摇 |
| **场景模板开箱即用**（P1-1） | **Typora / VSCode 均不带写作场景模板**（Obsidian 需装插件、Notion 模板为其卖点）——把块级能力打包成"插入即写"的模板，是免费产品里体验差异最直接的一档 | 先上内置 5~8 个模板，验证使用数据后扩 |
| **AI 辅助（用户自带 Key）**（P2-3） | 本地优先 + 可选 AI，兼顾隐私与能力 | 等主流程补齐后 |
| **主题/模板生态**（P2-1/P2-4） | 开放后由社区产出内容资产 | 长期护城河 |

## 7. 指标与埋点建议（落到可执行）

**北极星指标**：周活跃写作天数（WAD）—— 一周内至少打开并编辑过的天数 ≥3 视为活跃用户。

| 层级 | 指标 | 用途 | 数据来源（埋点事件） |
|---|---|---|---|
| 获客 | 新安装数、首次启动完成率 | 分发与 onboarding 效果 | `app_start(is_first)` |
| 激活 | **首日完成一次"插入+保存+导出"闭环的比例** | 检验 P1-3 引导效果 | `doc_create` + `doc_save` + `export_*_success` |
| 留存 | 次周留存、WAD、连续写作天数 | 检验 P1-7 | `app_active_day`（本地日历即可） |
| 价值 | 人均文档数、人均字数、功能使用广度（用过 N 类块） | 判断用户是否"用起来" | `feature_use{...}` |
| 交付 | 导出成功率（按类型）、降级项触发率 | 检验 P0-4 / P1-10 | `export_{type}_{success|fail}` |
| 健康 | 崩溃率、未保存退出比例 | 检验 P0-1 | `crash` / 草稿恢复次数 |

**隐私红线（必须写进设置页文案）**：默认关闭；不含文档内容、标题、路径、文件名；可一键关闭与一键清空本地统计。
