## 一、表格专项修复（用户指定需求）

### 1. 单元格拖拽选区四方向误选（长期缺陷）✅
- **原缺陷**：选中单元格后向上/下/左/右任一方向拖动扩展时，都会误选中鼠标未划过的单元格。
- **根因（v3.30 定版分析）**：轴向判定按「距起点的总位移」逐次评估（离轴 <40/80px 才锁定）——长距离拖动中手部弧线摆动必然越过阈值，轴向漂移成矩形（free），把鼠标从未划过的行/列**永久**拉进选区；四方向均复现。
- **修复**：起拖时按初始位移**一次性定轴并保持（sticky）**（`tblDragAxis`）：
  - 初始横纵位移都大（≥28px）→ 斜向矩形（宽表拖到右下角仍可整表选中）；仅横向明显 → 锁定横向只扩列；仅纵向明显 → 锁定纵向只扩行；
  - 锁定后只有「明显转向」才升级矩形：横向需离轴 >72px（约两行）且超过横向位移三成，纵向对称（>150px）——普通手部弧线（60~100px）不触发；
  - 叠加 5px 启动阈值、`elementFromPoint` 兜底与 rAF 节流，选区与鼠标实际划过路径一致。
- **验证**：探针 `_m30a`（已纳入 `_run_full.py` 常驻回归）11 项全 PASS——四方向弧线拖选、右拖终点落在下一行（旧逻辑必复现幽灵格、修复后无）、对角整表矩形；对照实验证实旧逻辑 A7 用例 FAIL（r1=3 幽灵行）、修复后 PASS。

### 2. 合并单元格移动对齐 Microsoft Office ✅
- **原缺陷**：移动表格中间区域的合并单元格行为不正确（含合并格时整体置灰或移动结果错误）。
- **语义确认**：经用户确认采用「**与左邻/上邻格交换（Office 常规）**」——例如一行 4 列 `[A][B][M(合并2列)][C]`，M 左移一格 → M 与 B 交换位置，A、C 原位不动，列数不变；上/下/右同理。
- **实现**：
  - 新增 `tblMoveCheck(m, r0, c0, r1, c1, dir)`：对四方向做「整带对齐」校验——选区带整体平移一格，相反侧相邻格必须恰为单行/单列格才允许补位；跨界（表头行/末行/越出表宽）与跨占一律拒绝并给出原因；
  - `tblOpOnModel` 的行/列移动重写为交换语义：带内整体平移，相邻单行/单列格补到带空出的远端；行样式按新行序重建，列宽 `colW` 随内容轮转；
  - 右键菜单四个移动按钮与实际执行共用 `tblMoveCheck` 判定，不可移动时置灰并显示原因，保证「菜单可点即可正确执行」。
- **验证**：合并格在表格中部左/右/上/下移动、含合并格选区整带移动、边界拒绝（表头行上移、最左列左移等）探针通过，列数与内容守恒断言通过。

### 2b. 合并中间单元格「跑到边缘」排查 ✅（根因 = 问题 1 的级联，合并定位逻辑本身无缺陷）
- **排查结论**：合并链路（`tblMerge` 锚点 = 选区左上格 → 删除被并格 → `tblModelToStorage` 按行序输出 colspan）逐环走查与探针验证均正确——程序化选区合并中间两格，结果 `<td>6</td><td colspan="2">7 8</td><td>9</td>` 停在原位，DOM `cellIndex=1`；真实拖选路径合并同样停在原位。
- **真实根因**：拖选误选（问题 1）使实际选区偏离用户意图——拖动中轴向漂移成矩形后，选区左上角落在边缘格，合并锚点随之落在边缘，看起来「合并格跑到边缘」。
- **修复**：随问题 1 的 sticky 定轴修复根治；`_m30a` B1~B3 用例（程序化选区合并、真实拖选合并、拆回还原）固化验证。

### 3. 表格全操作回归排查 ✅
对表格全部操作做了系统重验（内核 `test_core.js` 新增/扩充断言 + GUI 探针），覆盖：
- **选择**：单击、四方向拖选（轴向锁定）、斜向矩形、拖选 5px 阈值、选区外右键重置单选；
- **合并/拆分**：矩形区合并、合并后拆分（任意单格拆分 + 网格面板选跨度）、还原单元格、合并格上再选部分格的置灰判定；
- **移动**：普通行/列移动、含合并格整带移动（交换语义）、四方向边界拒绝；
- **插入/删除**：插行/列（继承格式）、删行（含表头行拒绝）、删列（最后一列拒绝）；
- **其他**：对齐左/中/右、清空内容、表格标注 `<caption>`（上/下）、整表缩放（合并格重放）、表格右键菜单项与实际行为一致。
- **排查结论**：各操作互不冲突；排查过程中一并修正了菜单置灰判定与执行逻辑不同源的问题（统一走 `tblMoveCheck`），未发现其他新缺陷。

### 4. 设置组框「嵌入式图例」样式 ✅
- 系统设置中「图片存储」「代码块外观」等所有组框标签改为**组框标题**：顶部边框线从标题文字垂直中点穿过，标题文字处边框断开，形成嵌入式图例效果（Qt QSS `subcontrol-origin: border` + 标题底色遮盖 + 强调色）。

### 5. 表格右键菜单横排分组（追加需求）✅
- 表格右键菜单中「行操作」「列操作」「合并和拆分操作」「移动操作」四组改为**图标横排**：组标题 + 同组图标按钮一行并列（对齐「对齐方式」的样式），保留分隔线；
- 每个图标按钮按当前选区动态置灰，置灰项 hover 显示**禁用原因**（如「选区含表头行不可删行」「未选中 ≥2 格不可合并」）；
- 菜单末尾保留纵向的「清空内容」「表格标注…」。
- **v3.30.2 更新**：应用户要求改为**上下文过滤**——不适用项整体隐藏（不再置灰占位），组内全部不可用 → 整组隐藏，分隔线只在可见组之间出现；详见下文「六、二次返工」第 2 项。

## 一b、二次返工（v3.30.1 / v3.30.2 · dist40 后用户反馈未修复）

### 1b. 拖选误选彻底修复：轨迹选区（v3.30.1 定版）✅
- **用户反馈**：dist40（sticky 轴向版）中四方向拖选仍误选、合并格仍「跑到边缘」。
- **新证据（真实输入复现）**：合成 MouseEvent 探针全绿但真实使用失败 → 新建 **OS 级 SendInput 真实鼠标输入探针 `tests/_m31.py`**，用真实系统输入复现并定位：
  - T4/T8（拖动终点偏离轴向）→ sticky 的「明显转向升级矩形」把未划过的区域拉进选区；
  - 起拖瞬间手部抖动一旦先在错误方向越过 28px，sticky 会**一次性锁错轴**；
  - 结论：任何「锚点→当前格」矩形模型都无法满足「选区与鼠标实际划过严格一致」。
- **修复（机制级重构）**：废弃轴向猜测，改为**轨迹选区**——
  - 选区 = 指针**实际扫过**的逻辑格集合（`tblTrail`，合并格记锚点），拖选中实时高亮轨迹；
  - 事件间可能跨格（快速拖动 / 合成单跳）→ 按 ~18px 步长插值 + `elementFromPoint` 补齐中途扫过的格；
  - 松开时轨迹定格进 `tblSel.trail`；包围盒由轨迹同步（`trailSyncBBox`），行/列带状操作（插删移动行列）照常按包围盒工作；
  - 逐格操作（清空 / 对齐 / 删除内容）以轨迹为准；合并要求轨迹恰好铺满包围盒（无洞），非矩形轨迹 → 合并项不显示；
  - 右键可在拖选未松开时弹出（真实操作）→ 菜单判定取实时轨迹（`tblTrailArr`）。
- **验证**：合成探针 `_m30a` 11/11 + 真实输入探针 `_m31` 10/10（均纳入 `_run_full.py` 常驻回归）：
  - 四方向直拖/带抖动 → 恰好本行/本列（轨迹逐格断言）；
  - **幽灵格判别用例**：右拖终点落下一行 → (3,1) 不入选；下拖终点落右列 → (1,2)(2,2) 不入选；对角拖 → 未划过角格 (0,4)(5,0) 不入选；
  - 合并定位回归：真实拖选/程序化选区合并中间两格均 `<td colspan="2">` 停在原位（DOM cellIndex 断言）。
- **合并「跑到边缘」**：确认为拖选误选的级联（选区锚点漂到边缘），随轨迹选区根治；合并链路本身经逐环走查无缺陷。

### 2b. 右键菜单上下文过滤（v3.30.2 · 用户新要求）✅
- **要求**：菜单只显示当前支持的操作，不支持的不显示（而非置灰展示）。
- **实现**：`buildTblbar` 重构为两段式——先收集「可用组」（`en===false` 的按钮直接剔除，组内全空 → 整组不收集），再统一渲染并在相邻可见组之间插分隔线；`disT` 置灰机制移除。
- **验证**：smoke17/28 断言全面适配（单格：合并/还原不显示、拆分可用；整列：拆分/还原不显示；整行：删除列不显示；多行多列：合并可用）；菜单可见项 = 可执行项逐项断言通过。
