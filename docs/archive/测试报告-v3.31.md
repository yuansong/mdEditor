## 4. 失败甄别记录（测试工程化留痕）

首轮 smoke33 出现 5 处 FAIL，逐一甄别（探针 `_m33b.py` + 源码核实）后定案如下——**4 处为测试脚本缺陷，1 处为真实产品缺陷**。测试脚本已修正并复跑全绿。

| 疑点 | 甄别过程 | 结论 |
|------|----------|------|
| G1「标签切换内容错乱」 | 探针 B/C：慢速切换 + 12 次快速压力切换（60ms 间隔）后内容均正确、`_switching` 无卡死。根因：测试断言差一——`n0=1` 时 `setCurrentIndex(n0)` 切的本就是 TAB1，返回 TAB1 内容是**正确行为** | 测试缺陷（已修正：补切 index 0 用例） |
| S1「自动保存未落盘」 | 探针 D：模拟真实点击块 + `execCommand('insertText')`（触发 `markDirty`）→ 3 秒内自动落盘且单换行结尾。根因：`setMarkdown` 显式 `state.dirty=false`（editor.html:5415），程序化注入**本就不应**触发自动保存 | 测试模拟方式缺陷（预期设计） |
| S1「版本快照数 0」 | 源码核实 `_history_dir`（mainwindow.py:840）用 `splitext` **去掉扩展名**作目录名；测试查了带 `.md` 的错误路径。逻辑闭环：磁盘写入成功 ⇒ 同一 try 块内的快照语句必然已执行 | 测试路径缺陷（已修正）。**文档勘误**：快照目录名为「文档名不含扩展名」 |
| E2「H7 渲染为 h7 元素」 | 源码核实渲染端 `Math.min(n,6)` 钳制（editor.html:1546）→ 实际渲染 `<h6>`；首轮选择器层级也写错（块为 DIV.blk 包裹） | 测试断言缺陷 + 引出 BUG-2（设计不一致） |
| E3「精确计数 120」 | 复算：`("针针，")×40` = 80 处，产品返回 80 正确 | 测试算术错误（已修正） |

## 5. Bug 清单

### BUG-1（P3 · 一般）管道表格表头含转义管道 `\|` 时整表降级为段落，且往返后块结构劣化

| 项 | 内容 |
|---|---|
| 所属功能 | C 表格（Markdown 管道表格渲染） |
| 严重程度 | **P3（一般）**——数据不丢失、可绕过（改用 HTML 表格或表头避开 `\|`），但渲染错误且结构劣化影响后续编辑 |
| 问题现象 | ① 表格不渲染（整块为段落 `b-p`，DOM 无 `<table>`）；② 经一次「渲染→收集」往返后，原 1 个表格块被拆成 2 个块（标题行独立成段，分隔行+数据行孤悬为另一块），表格语义彻底丢失 |
| 前置条件 | 无 |
| 复现步骤 | 1. 新建文档；2. 输入/注入三行管道表格，表头单元格含转义竖线：`列A\|B | 列C` 换行 `| --- | --- |` 换行 `\| 1 \| 2 \|`（即 `列A\|B | 列C⏎\| --- | --- \|⏎\| 1 \| 2 \|`）；3. 观察编辑区：该块显示为普通段落文本；4. 触发一次内容收集（切换标签或等待自动保存），再取 `getMarkdown()` |
| 预期结果 | 渲染为 2×2 表格，首格内容为 `列A\|B`（转义符不显示）；往返后仍为单个表格块 |
| 实际结果 | 渲染为段落文本 `列A\|B \| 列C`；往返后变为 `列A\|B \| 列C` + 空行 + `\| --- \| --- \|` + `\| 1 \| 2 \|`（结构劣化） |
| 定位建议 | 表格解析路径（`blockInfo` 表格分支 → `tblModelFromPipe`）：行内分列需按**非转义**竖线切分（Chromium 支持 `/(?<!\\)\|/`），且表头与分隔行列数校验应先剥离转义符再计数。怀疑表头分列与分隔行列数不一致导致回退为段落，随后段落写回路径按空行重排劣化结构 |
| 回归跟踪 | `tests/_smoke33.py` 已放置现状记录断言「BUG-1(现状记录)」；**修复后请将该断言改为 `table 数量 == 1`** |

### BUG-2（P4 · 轻微）「标题 7」语法渲染钳制为 h6、与标题 6 无差异且不入大纲

| 项 | 内容 |
|---|---|
| 所属功能 | B 编辑内核（标题语法）/ 斜杠菜单 |
| 严重程度 | **P4（轻微/设计不一致）** |
| 问题现象 | ① 斜杠菜单提供「标题 7」（`####### `），但标准 Markdown 仅支持 1~6 级；② 解析端识别为 h7（`blockInfo` `#{1,7}`），渲染端钳制为 `<h6>`（editor.html:1546 `Math.min(n,6)`），**与「标题 6」视觉完全一致**；③ `getOutline` 仅收录 h1~h6，标题 7 在大纲/目录中不可见 |
| 前置条件 | 无 |
| 复现步骤 | 1. 斜杠菜单 → 标题 → 标题 7（或手输 `####### 七级测试`）；2. 对比相邻的「标题 6」块外观；3. 查看大纲面板 |
| 预期结果 | （二选一，建议 A）A. 移除「标题 7」入口并按 6 级封顶，输入的 `#######` 提示或按正文处理；B. 保留 h7 扩展并使其可区分渲染、进入大纲，且在导出文档中说明非标准语法 |
| 实际结果 | 菜单可插入、渲染与 h6 无差异、大纲不可见，易误导用户 |
| 定位建议 | `SLASH_DEFS.heading.children`（editor.html:7374-7382）删除第 7 项；`blockInfo` 正则改 `#{1,6}`；相关 BM_HEADING_SUBS、raw-edit.t-h7 样式同步清理 |

## 6. 整体测试总结

**结论：v3.31 整体质量良好，可以发布。**

- 功能列表 12 个模块全部通过系统性测试（正常 + 边界 + 异常三态覆盖），全量回归 638 项 + 新增专项 51 项断言共 **689 项零失败**；
- 安全性：XSS 注入防护有效（脚本不执行、不进 DOM、原文保留）；
- 健壮性：所有 API 异常输入（坏 JSON、越界、非法区间、非法主题名、超界缩放）均被正确拒绝或钳制，无崩溃；
- 长文档能力：懒渲染阈值边界（399/400）、6 万字符单行、420+ 块文档的渲染/查找/大纲/导出全链路一致；
- 数据完整性：所有异常输入场景下 Markdown 原文往返无损（BUG-1 的结构劣化除外，字符仍不丢失）。

**修复优先级建议：**

| 优先级 | 项 | 理由与建议 |
|---|---|---|
| 1（本迭代） | **BUG-1 转义管道表格**（P3） | 唯一的功能性缺陷；触及 GFM 常见语法，技术笔记场景概率不低。修复点集中（表格分列正则 + 列数校验），回归成本低（改 smoke33 一条断言 + 复跑全量） |
| 2（随下次版本） | **BUG-2 标题 7**（P4） | 建议直接移除「标题 7」入口（方案 A），改动小且消除误导；涉及斜杠菜单项删除需同步 smoke 断言（历史经验：菜单变更必导致 smoke27/29 类断言过期） |
| 3（测试基建债） | D9：各 smoke 统一 QSettings 重置 setUp | 本轮再次出现设置项跨用例影响的处理成本（主题/缩放/打字机均需手动捕获还原），统一 setUp 可根治 |
| 4（低） | 功能列表文档随行更新 | 待确认项 #2 已验证销项；OBS-2 的快照目录名说明已勘误入档 |

### 8.1 BUG-1 转义管道表格（P3）——已修复 ✅

**根因**：不在分列（`parseRowLine` 已用 `(?<!\\)\|`），而在分块器 `splitBlocks` 的 `kindOf`——它只把「以 `|` 开头且以 `|` 结尾」的行识别为表格行，而 `blockInfo` 的表格判定遵循 GFM 允许表头不带首尾竖线。于是「裸表头（text 类）+ 竖线分隔行（table 类）」按类型不一致被强制拆块：表头独立成段落，分隔行+数据行成孤立块后也判不出表格 → 整表降级为段落，且「渲染→收集」往返后被拆成 2 块，结构劣化。

**修复**（`src/editor.html` splitBlocks，4 处）：

- 新增 `isSepRow()` 分隔行判定（竖线分隔的 `:?-+:?` 列，纯 `---` hr 因无竖线不误判）；
- 分组补两条规则：① 表头进入——当前块为空、本行含非转义竖线且下一行是分隔行 → 表格行；② 表体延续——表格块已开启、本行含竖线（转义亦算）→ 继续并入；
- `tblOpen` 状态随 flush 全路径复位；块首类型判定对已开启表格块取 `'table'`。
