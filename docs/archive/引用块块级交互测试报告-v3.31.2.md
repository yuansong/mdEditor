## 二、缺陷清单

### BQ-1【P3】块菜单「上移/下移」在边界不置灰，且存在死代码

- **复现**：文档只有一个块（或引用已是首块/末块）→ 悬浮手柄 → 块菜单。
- **预期**：唯一块时两项均置灰；首块「上移」置灰；末块「下移」置灰。
- **实际**：三种场景 `dis=false` 全部可点（点击后无效果但无反馈）。
- **根因**：`markBlockMenuBoundary()` 已定义（边界置灰逻辑）但**全文无任何调用点**——纯死代码，菜单构建时从未执行边界判定。
- **修复方向**：在块菜单打开路径调用 `markBlockMenuBoundary(firstIdx, lastIdx)`；或删除死代码并在 `openBlockMenu` 内联判定。
- **用户影响**：轻微（点了没反应），但违背「禁用态传达边界」的交互预期。

### BQ-2【P2】脚注定义块被上移/移动出文末后，退化为字面源码且编号对应断裂

- **复现**：文档 = 引用（含 `[^1]` 标记）+ 文末脚注定义块 → 对定义块执行「上移」。
- **预期**：定义块移动后仍识别为 fnbody，标记与定义对应保持。
- **实际**：定义块移到引用上方后渲染为**字面源码文本** `[^1]: 这是脚注定义的中文内容`（html 即原文本，无 fnitem 结构），`defs=[]`——脚注语义丢失；正文标记 `[^1]` 悬空。
- **根因**：fnbody 解析仅在文档**末尾连续区**识别 `[^n]:` 行；定义块被移出末尾连续区后按普通段落渲染，回写时也不再还原为定义。
- **修复方向**：① 定义块移动时拦截并提示「脚注定义需位于文末」（低成本）；或 ② 移动后重新归位到文末；或 ③ fnbody 识别支持任意位置的 `[^n]:` 行（成本高，不建议）。
- **对照**：删除定义块的表现是正确的（标记降级为 `[1]`，B14 ✅）。

### BQ-3【P2】外层格式 toggle 取消时，嵌套内层标记被切碎 → 渲染出字面 `**`

- **复现**（4 种块型 8/8 复现，`_m92`）：对文字依次「删除线 → 加粗 → 再点删除线（取消）」。
  - 段落 / 标题 / 列表 / 引用全部命中；
  - raw：`~~中文~~` → `~~**中文**~~` → **`~~**~~中文~~**~~`**（预期 `**中文**`）；
  - 渲染：`<del>**</del>中文<del>**</del>`，界面出现字面 `**`。
- **随机序列证据**（`_m90` D1 step22~26）：同一模式在 30 步随机序列中命中；后续「清除格式 T×」可一步自愈（step26 回裸文本）。
- **根因**：v3.31.2 的游程判定修复覆盖了「同游程粗斜」（FMT-5，`_m86` 124/124）与「链接外壳」（FMT-4，`_m84/_m85` 全过），但**未覆盖「不同 marker 的嵌套解包」**——取消外层 `~~` 时，紧邻字符是内层 `**`，判定未向外跳过内层标记寻找真正的外层游程，最终把 `~~` 插进了内层标记中间。
- **修复方向**：toggle 取消判定沿选区向外逐层剥壳（每层校验 marker 对），任一层匹配当前动作 marker 即解包该层、内层原样保留；与 FMT-4 的 `_oa/_ob` 外壳扩展合流为同一「逐层解包」实现。
- **用户影响**：界面出现字面 `**`（源码可见），可用「清除格式」自愈，故定 P2。

## 三、结论与亮点

**判定标准四项的最终结论**：
1. **渲染态保持** ✅：除 BQ-3 的字面 `**` 外，95 项断言覆盖的所有操作序列（含撤销/重做、快速连点、块转换）均未回退源码态、未裸露 Markdown/HTML；
2. **中文完整性** ✅：全部用例无乱码、无截断（含转代码块、转标题、复制块）；
3. **编号与标记同步** ◐：常规路径（初始、复制、删除定义）全部正确；**仅定义块被移动位置时断裂**（BQ-2）；
4. **悬浮按钮** ✅：出现/定位/吸附/隐藏/菜单展开全部正常（仅边界置灰缺失，BQ-1）。

**历史缺陷回归确认**：QUO-3（渐进退级）、QUO-5（no-op 菜单项移除）、FMT-2（链接 toggle）、FMT-3（清除格式含链接/行内码嵌套）、FN-3/4（脚注跳转与重排）在本轮引用块场景下全部保持修复。

**优先级建议**：BQ-3（P2，与 FMT-4/5 合流为「逐层解包」一次修）→ BQ-2（P2，低成本拦截方案即可）→ BQ-1（P3，一行调用 + 死代码清理）。
