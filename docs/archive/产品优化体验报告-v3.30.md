# mdEditor 产品优化体验报告（v3.30 · 2026-09-26）

> 报告对象：v3.30（dist40 开发基线）。
> 依据：本批修复实测（表格专项 5 项 + BUG 12 项 + 悬浮菜单自查项 11 项 + UX 12 项，见《修复报告-v3.30》）、全量回归记录、源码走查。
> 本报告为唯一基线版本，取代《产品体验报告-v3.29》与《UX优化建议报告》；后续迭代以此为准排期。

## 一、总评

**定位**：本地优先、免费、真 Markdown 的中文块级所见即所得编辑器。

**一句话结论**：本批「深度打磨」集中落地后，交互一致性与细节反馈已上一个大台阶——高频路径（加粗、删除、引用内嵌块、表格移动）的「静默失效/无反馈」类问题清零；下一阶段的主要矛盾回到 **结构性大项**：树形目录、粘贴转 Markdown、大文档性能。

**成熟度打分（满分 5）**：

| 维度 | 得分 | 变化 | 说明 |
|---|---|---|---|
| 功能完整度 | ★★★★☆ | — | 全链路可用；表格能力（合并/移动/标注）仍强于 Typora |
| 编辑体验 | ★★★★☆ | ↑ | 渲染态快捷键链路统一、浮层×格式栏共存、键盘导航补齐 |
| 性能 | ★★★☆☆ | — | 冷启动优秀；懒渲染仍是大项待办 |

## 二、本批体验提升要点（v3.29 → v3.30）

### 1. 表格（差异化标杆，本轮重点打磨）
- 拖选选区与鼠标划过路径严格一致（轴向锁定 + 迟滞），四方向不再误选；
- 合并单元格移动对齐 Microsoft Office（交换语义 + 整带校验），右键菜单实时置灰并显示原因；
- 右键菜单「行/列/合并和拆分/移动」四组图标横排，信息密度与操作效率提升。

### 2. 行内格式与浮层体系
- Ctrl+B/I/S 与格式栏按钮行为完全统一，「浮层打开时无法加粗」根治；
- 菜单与格式栏共存（有选区时格式栏保持显示）；块菜单补齐 ↑↓/Enter/Esc 键盘导航，边界项置灰带原因；
- 格式栏显示「已选 N 字」；删除类操作统一 toast「Ctrl+Z 可撤销」。

### 3. 数据安全与互通
- 保存沿用文件原编码（GBK 不再静默转码）；自动保存纳入版本历史（60 秒节流），默认配置下版本历史恢复可用；
- 「复制为 HTML」支持贴入微信/Word 保留格式；内嵌大图提示改用 assets；pandoc 未装导出前预警。

### 4. 引导与可发现性
- 图表/公式源码框一键「插入可运行示例」（此前 v3.26 报告 P0 项）；
- 斜杠菜单分组小标题；状态栏「⌘ 命令」入口；关于页版本号 + 更新日志直达；
- 全局搜索支持「仅文件名」；文件页顶部过滤框；导出/另存/图片对话框记忆上次目录。

### 5. 视觉打磨
- 系统设置组框改「嵌入式图例」标题（边框线穿过标题中点），设置页观感对齐现代桌面应用。

## 三、剩余优化项（基线清单）

### 高优先级补充（2026-09-27 增补，统一标记为高优先级）

> 来源：用户实测反馈 + 源码走查（标题级别显示检查、表格拖选方案评审）。
> 说明：拖选选区模型已由 v3.30.5/6「锚点-指针矩形」落地（选区=起始格与指针格的对角矩形），本节收录该轮评审中尚未覆盖的 2 项遗留优化，连同标题级别显示 2 项，共 4 项；均按「问题描述 → 优化方案 → 预期效果」结构收录，便于排期跟进。

**HP-1 ｜ 状态栏显示当前块类型（含标题级别）**
- 问题描述：光标进入标题块时，级别信息只在打开块菜单（⠿ 手柄 / Ctrl+/）后才可见（「当前块：标题 N」，editor.html:6393/6551）；右键标题块走系统菜单，无任何块类型信息；渲染态与编辑态仅靠字号和 H1/H2 底边线暗示级别，缺少随时可见的显式确认途径。状态栏目前只有「字数 · 阅读时长」「行 · 列」（mainwindow.py:292~299）。
- 优化方案：状态栏新增「当前块」标签。复用现有 `getCaretLineCol` 轮询通道增加 `type` 字段（editor 侧 `blockInfo(state.raw[editIdx]).type` 数据现成），Qt 侧在 `_pos` 旁加 QLabel 显示 `typeLabel(cur)`；光标进出块自动更新，特殊块显示「表格 / 图片 / 图表 / 公式」等。
- 预期效果：任何时刻瞥一眼状态栏即知当前块类型与标题级别，零遮挡、零学习成本；光标/选中标题即显示「标题 N」，直接回应「选中标题是否显示为几级标题」的诉求；同时为后续按块展示上下文（如代码块语言、引用深度）打好通道基础。

**HP-2 ｜ 表格拖选视口边缘自动滚动**
- 问题描述：拖选过程中指针到达编辑区上/下边缘即停止，要选的行数超过一屏时无法在一次拖选中完成，只能分多次选后再合并操作（v3.30.5 零阈值矩形模型下的功能缺口）。
- 优化方案：拖选期间（`tblDrag=true`）检测指针距编辑区视口上/下边缘 < 24px 时启动 rAF 自动滚动（约 12px/帧），每帧用最后指针坐标重跑命中判定与矩形更新；松手或指针离开边缘区域即停。
- 预期效果：一次拖选即可跨屏选中任意行数的区域，对齐 Excel / WPS 长表格选择习惯；滚动速率固定可控，不引发布局跳动。

**HP-3 ｜ ⠿ 块手柄 tooltip 显示块类型**
- 问题描述：悬停块手柄无任何提示，需点击打开菜单才能确认块类型与标题级别，确认成本多一步（手柄无 title 属性，源码走查确认）。
- 优化方案：`BH.title = typeLabel(blockInfo(state.raw[idx]).type)`，随 hover 所在块动态更新，实现约一行。
- 预期效果：悬停即见「标题 3 / 引用 / 有序列表」，块类型确认零成本；与 HP-1 形成互为冗余的双重确认通道。

**HP-4 ｜ 拖选起始格视觉标识**
- 问题描述：v3.30.5 矩形选区由「起始格 + 指针格」定对角，但两种角色格在视觉上无区分，长距离拖选时用户不易确认起点是否选对，也难以感知选区的构造规则。
- 优化方案：拖选进行中给锚点格加 1.5px 描边（或加深底色），与普通高亮格区分；松手定格后保留至选区消失。
- 预期效果：选区构造规则「可见」，减少选错起点后的返工；与 HP-2 组合形成长表格拖选的完整体验。

### 分割线插入专项排查补充（2026-09-27 增补）

> 来源：源码链路走查（入口 → 插入 → 光标 → 删除 → 撤销 → 导出）。
> 基线结论：分割线基本链路健康——斜杠菜单插入行为正确（置脏 + 快照 + 光标落下一块，editor.html:6152~6169）、`---`/`***`/`___` 均识别（1298）、引用内嵌正常、块间空行 join 无 setext 歧义（5223）。以下为排查发现的缺陷与优化项，HR-1~HR-3 为真实缺陷，建议优先处理。

**HR-1 ｜ P1 · `goToBlock` 缺 hr 分支，三条路径把光标推进 `---` 源码态**
- 问题描述：`goToBlock`（editor.html:2353~2380）只特判 table/fence/标题/列表/引用，hr 落入兜底 `enterEdit(i, 0)`，整块变成显示 `---` 的可编辑文本。受影响入口：① 方向键上下跨分割线（3228/3229 直接调 goToBlock）——写作中按 ↓ 分割线突变成一行 `---`；② `Ctrl+Shift+-` 菜单插入（cmd 'hr'，5316）——插入后光标停在 `---` 上，而斜杠菜单同操作正确跳到下一块，同一功能两条链路行为不一致；③ 点击文档尾部空白（goToEditableEnd 2386 只特判 fence/图片）。与 4432 行注释「分割线无内容可编辑、保持渲染态」的设计意图直接矛盾，属遗漏而非设计。
- 优化方案：`goToBlock` 补 hr 分支——目标块为 hr 时跳到下一块（i+1，无则按 slash 路径 6165~6169 同款逻辑追加空块再进入）；`goToEditableEnd` 的末尾块特判同步补 hr。
- 预期效果：方向键/菜单插入/点空白三条路径光标永远落在可编辑文本上，分割线在写作流中保持「透明」；两条插入链路行为统一。

**HR-2 ｜ P2 · `cmd('hr')` 缺 `markDirty()/scheduleSnapshot()`**
- 问题描述：快捷键/菜单插入分割线（editor.html:5316~5322）对比斜杠路径（6156 两者均调用）缺少置脏与快照：① `state.dirty` 不置位，关闭文档不提示保存，改动可能丢失；② 无 undo 快照，下一次编辑的快照把「插 hr + 该次编辑」打包成一步，`Ctrl+Z` 一步退两件事，撤销粒度被破坏。
- 优化方案：cmd 'hr' 分支补 `markDirty(); scheduleSnapshot();`（两行）；同族核对 `cmd('table')`、`cmd('math')` 等插入型 case 是否同样遗漏。
- 预期效果：消除静默丢稿风险；分割线插入可被单独撤销，撤销粒度与其他插入操作一致。

**HR-3 ｜ P2 · 分割线下方非空段落行首 Backspace，分割线被吞**
- 问题描述：Backspace 特判（3621）只覆盖「空段落上方是 hr → 整线删除」；非空段落行首 Backspace 落到通用合并（3662）：`state.raw[i-1] = '---' + raw` 合成 `---正文` 一段，hr 正则不再匹配，分割线静默消失、行首冒出 `---` 字样。图片/代码块上方的同类场景均有专门拦截，hr 漏了。
- 优化方案：Backspace 行首分支（off===0）对上方 hr 补拦截：与空段行为对齐——删除整条分割线、文本保留（或仅光标不动），禁止通用合并路径触碰 hr raw。
- 预期效果：分割线不再被键盘操作静默吞掉，删除途径收敛为「相邻空段 DEL/Backspace」与右键菜单两条明确路径。

**HR-4 ｜ P3 · 分割线删除可发现性差**
- 问题描述：分割线本体不可点选（4436 直接 return，无任何反馈），删除只能靠「相邻空段按 DEL/Backspace」或右键菜单，新用户基本找不到删除入口。
- 优化方案：点击 hr 给选中高亮态（描边），选中态按 Delete/Backspace 直接删除；或 hover 时轻提示。
- 预期效果：删除入口可视化，所见即可删；与块菜单形成双通道。

**HR-5 ｜ P3 · 块菜单缺「复制块」**
- 问题描述：hr 的特殊块菜单只有上移/下移/删除（6763），表格有复制块；连续插多条分割线只能反复走斜杠菜单。
- 优化方案：hr 菜单补「复制块」项（当前块后插入同内容块，复用 dup 逻辑）。
- 预期效果：连续分割线场景一步完成；特殊块菜单能力对齐。

**HR-6 ｜ P3 · 输入侧无自动转换反馈**
- 问题描述：正文输入 `---` 提交后隐式变线（语义正确），但没有 Typora 式「回车确认转换」的显式反馈，属隐式突变；`***` 同理。
- 优化方案：可暂不改行为，仅记录；若后续对齐 Typora，输入 `---`/`***` 回车时显式转 hr 并给出轻提示。
- 预期效果：转换意图显式化，消除「打的字变成线」的困惑。

**HR-7 ｜ P3 · 多行块以 `---` 开头时渲染丢弃余下行**
- 问题描述：`blockHTML` 的 hr 分支（1390）无条件返回 `<hr>`，源码模式把 `---` 与后续文字并进同一块（删空行即可构造）时，余下文本行在写作模式不显示（raw 仍保存不丢数据，但显示误导）。
- 优化方案：hr 渲染分支对 `lines.length > 1` 的块做兜底——余下行按段落渲染，或分块时拆开。
- 预期效果：显示与 raw 一致，消除「内容看不见」的误导。

> 修复优先级：HR-1（补一个分支，收益最大）→ HR-2（两行代码，消除丢稿风险）→ HR-3（对齐图片/代码块既有拦截模式）→ HR-4/HR-5 打包进打磨版。

### 图片插入与操作专项排查补充（2026-09-27 增补）

> 来源：源码链路走查（插入 → 存储 → 选中/操作 → 删除 → 导出）。
> 基线结论：图片模块是编辑器成熟度最高的子系统之一——四条插入通道（Qt 统一插入面板 mainwindow.py:1007、剪贴板粘贴 editor.html:5197~5221、拖拽落窗 2181~2189、Markdown/HTML 原生语法）、双存储模式（assets 落盘 / embed 内嵌）+ 双向互转 + 批量迁移（1315~1353）、选中态操作条（重命名/转换/图注/等比缩放）、DOCX 相对路径解析与 EPUB 图片收集均完备。缺口集中在导出完整性与容错反馈，IMG-1~IMG-3 为建议优先项。

**IMG-1 ｜ P2 · 拖入多张图片只插入第一张，无任何提示**
- 问题描述：`dropEvent` 循环内命中图片文件即 `break`（mainwindow.py:2187~2189），拖 5 张图只进 1 张，其余被静默忽略——用户无从得知是「失败」还是「成功但只收一张」。
- 优化方案：去掉 break，循环插入全部图片（每张独立块，逐张走既有插入通道），插入完成后状态栏提示「已插入 N 张图片」。
- 预期效果：批量插图（截图汇报、相册整理）一次拖入完成；行为与用户预期一致。

**IMG-2 ｜ P2 · 导出 HTML 不携带图片**
- 问题描述：`getExportHTML` 原样保留相对路径 `src`，导出的单文件 HTML 发给别人图片全裂；assets 目录也不随导出复制。同类的 EPUB 导出已有图片收集逻辑（exporters.py:447~453、547~548），HTML 缺了这一环。
- 优化方案：导出 HTML 时提供二选一——① 图片内嵌为 data URL（复用内嵌转换通道，单文件自包含）；② 复制 assets 目录到导出位置并改写相对路径。做成导出对话框选项，默认内嵌。
- 预期效果：导出的 HTML 独立可分享，补齐「复制为 HTML / 导出 HTML」互通闭环的最后一块。

**IMG-3 ｜ P2 · 图片加载失败无占位提示**
- 问题描述：相对路径图片被移动/重命名/删除后，编辑区只显示 Chromium 碎图标，无「图片缺失」说明，用户不知道源码还在、也不知道该去哪修。
- 优化方案：`img.onerror` 时渲染占位框（虚线边框 + 「图片缺失：文件名」文字），占位框仍可选中，操作条保留「修改存储文件名/重选图片文件」入口。
- 预期效果：断链图片从「无声的碎图标」变成可识别、可修复的对象，容错反馈对齐正文其他模块。

**IMG-4 ｜ P3 · 无点击放大预览（lightbox）**
- 问题描述：全文无灯箱实现，查看大图细节只能靠拖手柄缩放原图；Typora/主流编辑器均有点击放大。
- 优化方案：非选中态双击图片打开灯箱预览（原尺寸/适窗缩放，Esc 或点击遮罩关闭），与选中态单击不冲突。
- 预期效果：看图细节零成本，对齐同类编辑器基本预期。

**IMG-5 ｜ P3 · 图片无对齐控制**
- 问题描述：表格有对齐、文本有多级，图片无对齐入口（居中/左/右），需要写 HTML 才能实现。
- 优化方案：操作条加三个对齐按钮，写入 figure 的 `text-align`/`margin` 样式，随尺寸一起持久化。
- 预期效果：图文混排（左文右图等）无需触碰 HTML。

**IMG-6 ｜ P3 · 远程图片无批量本地化**
- 问题描述：插入 http(s) 图片存裸 URL，断网/防盗链即裂图；逐张手动「转为相对路径」对多图文档太繁琐（且该转换只处理内嵌场景）。
- 优化方案：文件菜单加「下载全部远程图片到 assets」——遍历文档内 http 图片，下载落盘并替换为相对路径（与既有「迁移内嵌图片为文件」互为镜像）。
- 预期效果：文档自包含、离线可用；网络图片资产化。

**IMG-7 ｜ P3 · 缩放无精确尺寸输入**
- 问题描述：图片尺寸只能手拖，操作条显示 `宽 × 高`（editor.html:9067）但不可编辑；需要精确尺寸（如统一 600px 宽）时只能反复拖拽试。
- 优化方案：尺寸标签点击变输入框（支持像素与百分比两种输入），Enter 确认写回源码。
- 预期效果：多图文档可批量对齐到统一宽度，尺寸控制从「手感」变「数值」。

- 优化方案：分两级——短期：编辑聚焦引用时像代码区 codePlain 一样还原源码标记显示（所见即源码，失焦再渲染），杜绝静默剥离；长期：最小化重写（只回写被编辑行）+ 行内标记往返映射。
- 预期效果：消除引用（与标题）内最高频写作场景的静默丢格式风险。

**QUO-2 ｜ P2 · 引用内 `/` 触发不限空行，插入位置却固定在块尾**
- 问题描述：普通块要求空块才触发 `/`（6982），引用内任意位置键入 `/` 都触发（6968 无空判断），但插入一律 quoteAppendBlock 追加到块尾（6530~6534）——光标在中间行插入，内容却出现在末尾，感知为「插错位置」。
- 优化方案：quoteAppendBlock 支持按光标行插入（拆行到 caret 行）；或触发收敛到「空行 / 行尾」，与普通块语义对齐。
- 预期效果：插入位置符合直觉；触发条件与正文一致可预期。

**QUO-3 ｜ P2 · 行首 Backspace 整块转段落过于激进，且经 QUO-1 路径丢结构**
- 问题描述：引用行首按 Backspace 把整块压成纯文本段落（3476~3491，qtext 为纯文本序列化）——含嵌套层级或内嵌表格/代码的引用，一个退格全没（嵌套 `> >`、qblk 原文全部扁平化）。
- 优化方案：行首 Backspace 改为「当前行退一级嵌套」（对齐 Shift+Tab 的行级语义），层级退光后再转段落；转段落保留嵌套标记为文本。
- 预期效果：破坏面从整块收敛到单行；与 Tab/Shift+Tab 心智模型一致。

**QUO-4 ｜ P3 · Tab/Shift+Tab 只作用于光标行，多行选区不批量缩进**
- 问题描述：嵌套增减按 quoteCaretOff 折叠光标定位单行（3381~3383），有多行选区时按 Tab 仅缩进光标所在行，选区被忽略。
- 优化方案：选区非空时对选区覆盖的行批量增减前缀（对齐代码编辑器习惯）。
- 预期效果：整段引用层级调整一步完成。

**QUO-5 ｜ P3 · 块菜单对引用无精简，含自身 no-op 项**
- 问题描述：引用块显示完整「转为」分组（含「转为引用」自身，7241），与代码块的精简菜单（7145~7157）风格不一；且「转为段落/标题」转换走纯文本路径，与 QUO-1 同源丢行内格式。
- 优化方案：引用的「转为」分组隐藏「引用」自身；转换路径在 QUO-1 修复后自动获益。
- 预期效果：菜单能力面精确；转换不再丢格式。

**QUO-6 ｜ P3 · 粘贴块级内容进引用降级为字面文本行**
- 问题描述：pasteMdInto BLOCKQUOTE 把粘贴内容当纯文本插入（4142~4144）——粘贴含表格/围栏的 Markdown 到引用内，得到 `> | A | B |`、`> ``` ` 字面行，不渲染为 qblk 富块。
- 优化方案：粘贴后检测块级语法（表格/围栏/图片），改走 quoteAppendBlock 路径生成内嵌富块。
- 预期效果：引用内粘贴与 `/` 插入能力面一致。

**QUO-7 ｜ P3 · 内嵌块受限文案与实际能力面不一致**
- 问题描述：qblk 的 hover 文案与点击反馈只提「表格 / 代码块」（1517、5640），实际列表/图片等一切富块内嵌同样只读，文案覆盖不全。
- 优化方案：文案改为「引用内的富内容块暂不支持直接编辑」。
- 预期效果：小改动，消除理解偏差。

**小项汇总**：`cmd('quote')` 为编辑态路径（toggle 时引用原文 `> ` 短暂可见，与渲染态编辑并存，可接受）；嵌套深度无上限（Tab 连按无限嵌套，暂无副作用）；空引用渲染与聚焦路径已妥善处理（`&nbsp;` + setCaret）。

> 优化优先级：QUO-1（P1 数据丢失，短期方案改一处即可止血，标题同源问题可一并修）→ QUO-2/QUO-3（P2 交互语义）→ QUO-4~QUO-7（P3 打磨，可打包）。

#### B. 问题清单

**FN-1 ｜ P2 · 引用块渲染态内插入脚注静默失效**
- 问题描述：引用内 `/` 菜单可打开（v3.29，6970-6979），但「脚注引用」走 `cmd('footnote')` 后被守卫 `fi<0||!editEl()` 静默拦截（5541——引用渲染态无 `.raw-edit`）；「脚注定义」走通用路径的 `if(i<0||!el) return`（6622-6624）同样静默失效。表格/代码/图片/分割线均已补 quote 分支，footnote/deflist 漏网。
- 优化方案：脚注引用是行内语法，在引用内完全合法——仿 BUG-2 为其补 quote 分支；脚注定义与定义列表在引用内无 Markdown 语义，菜单项置灰 + toast「该类型不支持在引用内插入」。
- 预期效果：消除静默失效，与既有 quote 分支策略对齐。

**FN-2 ｜ P2 · DOCX/EPUB 导出丢失脚注语义**
- 问题描述：exporters.py 自研解析不识别脚注——`parse_inline`（132-157）无 `[^id]` token，引用按字面 `[^1]` 文本输出；`[^1]: 说明` 定义块落入普通段落（120-128），字面标记原样可见。HTML 导出走编辑器渲染器，不受影响。
- 优化方案：DOCX 优先用 Word 脚注/尾注对象，降级方案为「正文 [n] 上标 + 文末编号列表」；EPUB 导出复用编辑器 HTML 渲染结果即可保留。
- 预期效果：导出物语义完整，不留原始标记。

**FN-3 ｜ P2 · 点击脚注引用无跳转**
- 问题描述：applyFootnoteTips 只回填 hover title（2324-2345）；引用 `<a href="#fn-id">` 在编辑区内点击仅落光标，不跳转到定义块；反向（定义 → 引用）也没有。Typora 支持双向跳转。
- 优化方案：单击/Ctrl+单击引用 → goToBlock 跳到定义块并短暂高亮；fnmark 反向跳回引用位置。
- 预期效果：长文档脚注核对效率明显提升。

**FN-4 ｜ P3 · 编号策略缺陷：字面文本占号 + 删除后复用乱序**
- 问题描述：nextFootNum 对全文 raw 做 indexOf（6697-6708）——代码块或行内码里的字面 `[^1]` 也占用编号导致跳号；删除中间脚注后新脚注复用该号，正文出现顺序与编号可能不一致；无「按出现顺序重排」机制。
- 优化方案：编号扫描跳过 fence/行内码片段；提供重排入口（保存/导出前自动或块菜单手动）。
- 预期效果：编号稳定、与出现顺序一致。

**FN-5 ｜ P3 · 孤儿定义无管理**
- 问题描述：删除引用后文末 `[^n]:` 定义残留，仍渲染为「脚注」区块；无未引用检测、提示或一键清理。
- 优化方案：状态栏轻提示 + 块菜单/命令面板提供「清理未引用脚注定义」。
- 预期效果：文档不留垃圾块。

**FN-6 ｜ P3 · hint 触发边界（可接受，建议文档说明）**
- 问题描述：`[^` 触发要求 e.key==='^' 且光标前文本以 `[^` 结尾（7001-7011）——词中间输入 `[^` 也会弹菜单（字面输入需 Esc）；全角符号与 IME 组合态（keyCode 229）不触发。`:` 仅空块触发，规则合理。
- 优化方案：保持现状，在帮助文档注明触发条件与关闭方式。

**DL-1 ｜ P2 · 渲染态无法新增第二个术语（dt 结构缺口）**
- 问题描述：解析器支持一块内多对「术语+定义」（1337-1340、1549-1555 任意非冒号行均渲染为 dt），但渲染态 Enter 一律新增 dd（3326-3336）——多术语对结构（术语A: 定义 / 术语B: 定义）在渲染态永远构造不出来，必须转源码手写。
- 优化方案：空 dd 上回车 → 升格为新 dt（Typora 风格「空定义项回车退出/转术语」）；或 Shift+Enter 新增术语。
- 预期效果：覆盖最常用的多术语定义列表结构，无需碰源码。

**DL-2 ｜ P3 · dt/dd 内行内格式快捷键静默失效**
- 问题描述：dt/dd 为 plaintext-only 渲染态编辑，`cmd('bold')` 依赖 `editEl()`（B13 同族，与 QUO-1 同根因）——Ctrl+B/I 在定义列表内无任何反馈。
- 优化方案：并入 QUO-1 的渲染态行内格式统一方案一起修。
- 预期效果：行内格式全块型一致。

**DL-3 ｜ P3 · Tab/Shift+Tab 行为未定义**
- 问题描述：dt/dd 上 Tab 走浏览器默认移焦点，键盘流断裂。
- 优化方案：Tab 在 dd 末尾新增定义（或插入固定缩进），Shift+Tab 退出定义列表。

**DL-4 ｜ P3 · 回写不保真与空定义边界**
- 问题描述：① syncDeflistEl 统一回写顶格 `: `（3247），用户原文的缩进（`  : 定义`）丢失；② 空定义回写成 `: `（无内容），下一轮 `:\s+\S` 解析不匹配 → 块类型漂移；③ rebuild 后空 `<dd></dd>` 高度为 0，无法点中聚焦。
- 优化方案：回写保留原始缩进；空 dd 回写占位空格或渲染 `&nbsp;` 保底可点。
- 预期效果：往返编辑无损。

**DL-5 ｜ P2 · 导出丢失定义列表语义**
- 问题描述：同 FN-2 根因——`术语\n: 定义` 在 DOCX/EPUB 导出为普通段落，字面冒号直接可见。
- 优化方案：DOCX 降级为「术语（加粗）+ 缩进定义段」；EPUB 走 HTML 渲染保留 `<dl>`。
- 预期效果：导出物可读。

#### C. 合并「脚注」与「定义列表」为一个一级菜单（需求评估）

- 现状：`/` 菜单一级 11 项平铺，`footnote`（含 2 子项）与 `deflist`（叶子）相邻（6391-6404）；Qt 设置页 `MENU_ITEMS` 同步维护同一份 11 项清单（dialogs.py:24-27）。
- **建议方案（推荐）**：合并为「脚注 / 定义」一个一级项，children = [脚注引用， 脚注定义， 定义列表]，**沿用 id `footnote`**；从 `SLASH_DEFS`、`SLASH_ORDER_DEFAULT`、`MENU_ITEMS` 移除 `deflist`。老配置由 mergeSlashOrder 自动过滤失效 id（supsub 先例，6400-6401），无迁移成本。
- 收益：① 一级菜单 11→10 项，降低视觉负担（此前已按同样理由移除 supsub）；② 两者同属低频学术/术语写作元素，场景高度重叠（术语解释常配合脚注），归组符合心智模型；③ `[^` 与 `:` 的提示菜单触发链路完全独立于 `/` 菜单配置，合并零影响；④ deflist 以 `t` 模板子项进入通用插入路径，现有 slashApply 分支原样复用，子项默认记忆（`sub.footnote`）照常生效。
- 成本：低——editor.html 两处定义 + dialogs.py 一行 + 设置页文案；无数据迁移、无快捷键变化。
- 风险：已保存的自定义顺序中 `deflist` 位置丢失（并入 footnote 组，可接受）；搜索「定义」仍可通过子项匹配命中（slashFiltered 已支持子项匹配保留父项，6462-6467）。
