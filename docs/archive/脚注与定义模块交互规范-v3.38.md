## 1. 交互规范

### 1.1 两个模块的关系与定位

「脚注」（footnote）与「定义列表」（deflist）语法形态相近（都含冒号行），但语义与渲染位置完全不同，故合并为一个一级菜单「脚注与定义」（`editor.html:8904`，v3.31.3 REFS-1）：

| | 脚注 | 定义列表 |
|---|---|---|
| 语法 | 正文 `[^id]` + 文末 `[^id]: 说明` | `术语` 行 + `: 定义` 行 |
| 渲染位置 | 引用留在正文，定义**集中渲染在文末** `.fnbody` 区 | 原地渲染为 `dl.deflist`，不移动 |
| HTML 语义 | `sup.fnref > a[href=#fn-X]` ↔ `.fnbody>.fnitem#fn-X` | `dl.deflist > dt + dd` |
| 编辑模型 | 渲染态编辑 `.fnedit`（失焦回写） | 渲染态直接编辑 dt/dd（input 即回写） |
| 语法标准 | MultiMarkdown / Pandoc 扩展 | PHP Markdown Extra（Pandoc、kramdown、Python-Markdown、Hugo 采纳） |

### 1.2 入口与触发时机

| 入口 | 触发 | 行为 | 实证 |
|---|---|---|---|
| `/` 菜单 | 空块（或非空块行首）键入 `/` → 一级项「脚注与定义」 | 二级：脚注引用 / 脚注定义 / 定义列表 | G1' ✅ |
| `[^` 快捷提示 | 编辑态文本以 `[^` 结尾 | 弹提示浮层两项：「脚注引用 `[^1]`」「脚注定义 `[^1]: 说明`」 | G3 ✅ |
| `:` 快捷提示 | **空块**键入 `:` | 弹提示浮层：「≣ 定义列表 术语 + : 定义」 | G4 ✅ |
| 右键菜单 | 右键脚注定义块（`.fnbody`） | 「按出现顺序重排编号」「清理未引用的脚注定义」 | H1 ✅ |
| 菜单插入后 | 插入「术语定义」 | 光标经 `preferDD` 直接落到第一行定义（REFS-4） | 代码 2167-2178 |

**前置约束**：`/`、`[^`、`:` 提示均要求 `state.editIdx >= 0`（源码态 `t-src` 块排除）——渲染态块需先单击进入编辑态（9721-9724）。探针 G1 首跑 FAIL 即因未建编辑态，属伪影。

### 1.3 展示层级与结构渲染

- **脚注引用**：`<sup class="fnref"><a href="#fn-X" data-fn="X">[X]</a></sup>`（1356）。**渲染是无条件的**——即使文档中没有对应定义也照常渲染上标（A1/A2 ✅）。
- **脚注定义**：文末 `.fnbody` 聚合区，每条 `.fnitem#fn-X` = `.fnmark([X] 标记，不参与编辑)` + `.fnedit(正文，contenteditable=plaintext-only，失焦回写)`（1779-1788）。空定义挂 `data-ph="脚注说明"` 占位提示。
- **定义列表**：`dl.deflist > dt + dd`，dt/dd 均 contenteditable（2107-2113）。空 dd 渲染占位提示「定义内容」（存储仍为 `": "`，REFS-4）。定义内容为空时 `: ` 不产生空格尾巴。
- **编号自动重排**：渲染按引用出现顺序分配编号，与 raw 中的 id 无关（D5 ✅：`丙[^2]，甲[^1]` 渲染后重排为 `[^1]=丙处`）。

### 1.4 悬浮与点击

| 交互 | 规范行为 | 实证 | 与竞品差距 |
|---|---|---|---|
| 悬停脚注引用 | 原生 `title` 提示脚注内容（B1 ✅） | `.fnref a` 与 `.fnmark` 均回填 title | Typora 是**自定义悬浮窗**即时预览；原生 title 有 ~1s 延迟、样式不可控、触屏不可达（观察项 B3，未立项） |
| 点击脚注引用 | `preventDefault` → 定位到文末定义块 `scrollIntoView(center)` + `.fn-flash` 高亮 1.2s（B4 ✅） | 7730-7743 事件委托 + fnFlash(7698) | Typora 同为点击跳转；早期版本需 Ctrl+点击，后改直接点击 |
| 点击 fnmark `[1]` | 跳回**首个**引用位置 + 高亮（B5 ✅） | fnJumpToRef(7717) | Typora 在定义后渲染 ↩ 回跳链接，我方以 fnmark 承担回跳，等价 |
| 点击无定义的引用 | toast「未找到脚注定义 [^X]」（B6 ✅，_m106c 实锤） | fnJumpToDef 7715 | — |

### 1.5 同位置同时命中的优先级与合并

- **优先级**：块首行形如 `[^1]: …` 且次行 `: …` 时，**判为脚注定义**（fndef），定义列表语法被吞入脚注正文（C1 ✅：`'第一条说明\n: 当作定义的第二行'` 整体成为脚注内容）。裁定合理：`[^id]:` 前缀更特异，fndef 优先级 > deflist。
- **合并（嵌套承载）**：脚注引用可出现在定义列表内部且功能完整——
  - dd 内（C2 ✅）：`术语甲\n: 定义内含脚注[^2]` → 引用渲染、title 回填、跳转链路完好；
  - dt 内（C3 ✅）：`术语[^3]\n: 定义` → 同上。
  - 反向不成立：定义列表语法不能进入脚注定义内部（见 1.5 优先级——被吞并）。

### 1.6 重复复用规则

| 场景 | 规范行为 | 实证 |
|---|---|---|
| 同一 id 多处引用 | 各自渲染上标（不合并显示 `[1][1]`），共享同一定义块（D1/D2 ✅） | refs=3、fnitem=2 |
| title 回填 | 每个引用的 title 均为同一份定义内容（D3 ✅） | — |
| fnmark 回跳落点 | 跳到**首个**引用（非「来源处」——渲染态已无来源信息）（D4 ✅） | blkIdx=0 |
| 编号 | 按出现顺序重排，与 raw id 解耦（D5 ✅） | — |
| 孤儿定义清理 | 右键「清理」移除未被引用的定义，被引用的保留（D6 ✅） | `[^5]` 移除、`[^1]` 保留 |

### 1.8 编辑与回写（两套通道，易混淆点）

| 区域 | 回写通道 | 触发时机 | 实证 |
|---|---|---|---|
| `.fnedit`（脚注定义正文） | **blur 事件** → `syncFndefEl`（2122/2127）：fnmark 取编号 + fnedit 纯文本 → `[^n]: 内容` | 失焦 | E1 ✅；多行续行（4 空格缩进）不丢失（E2 ✅） |
| dt/dd（定义列表） | **input 事件** → `syncDeflistEl`（4620/4548）：按 DOM 顺序映射回「术语 / : 定义」行，保留原 dd 缩进 | 每次输入 | E3'/E4' ✅ |
| 世代校验 | fnedit 挂 `__docGen`（2121，v3.37 DOCGEN-1） | 换文档后旧元素失焦回写**一律丢弃**（防写错文档） | — |

> 注：fnedit 是「失焦回写」、dt/dd 是「即时回写」，二者不一致但各有道理（fnedit 在文末聚合区，即时回写会频繁打断）；如后续统一需权衡快照频率。

### 1.9 模式与往返

- 源码 ↔ 渲染往返 raw 不漂移（H2 ✅）：`正文[^1]。\n\n术语甲\n: 这是定义\n\n[^1]: 这是脚注说明` 全等往返。
- 右键「重排编号」（`__fnRenum`）、「清理未引用」（`__fnClean`）在源码模式锁定（editorLocked），与全局块菜单一致。

## 3. 竞品对比

### 3.1 脚注

| 能力 | mdEditor v3.38 | Typora | Obsidian | 语雀/飞书文档 |
|---|---|---|---|---|
| 语法 | `[^id]` + `[^id]: 说明`（MultiMarkdown 系） | 同左（MultiMarkdown 扩展） | 同左 | 富文本脚注入口（无语法层） |
