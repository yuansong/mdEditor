## 二、按钮矩阵结果：按钮层高度统一 ✅

单一 `buildFloatbar` 工厂（editor.html:7374-7433）+ 三个上下文开关（`fbDelOnly`:7578 / `cellFormatCtx`:7586 / h1State:8348），**不存在按块型硬编码的按钮组分叉**。实测矩阵：

| 上下文 | 按钮 | 判定 |
|---|---|---|
| 段落 / 列表 / 引用 / dt / dd / fnedit | 粗体·斜体·下划线·删除线·高亮·行内码·链接·清除格式（8 钮） | ✅ 一致 |
| 标题 1 | 全套 + **⇔ 居中切换**（v3.31.2 #4，仅 h1） | ✅ 符合设计 |
| 标题 2-6 | 全套，无 ⇔ | ✅ 符合设计 |
| 表格单元格（管道 + HTML 双表型） | 全套 + **「＋」块级插入** | ⚠ 唯一分叉——即上轮 TBL-F2（与 `/` 菜单冗余 + 层级错位），维持移除建议 |
| 代码块 / mathdl / mermaid | **仅「删除整个块」**（delOnly） | ✅ 一致（`fbDelOnly` 对 `.codeblock/.mermaidblock/.mathblock`/图片统一命中；mathdl 与旧 math 共用 `.mathblock`:1582/1713 无遗漏） |

## 三、动作语义层：单元格路径与正文路径实现分叉 ⚠

两条路径的映射与守卫机制对比（这是「代码一致性」的核心发现）：

| 机制 | 正文路径 | 单元格路径 |
|---|---|---|
| 选区定位 | `lineAwarePlain` 行感知精确偏移（7506-7531）→ `mapPlainToRaw` 按块型跳前缀（1849-1915，覆盖 h1-6/quote/list/deflist/fndef） | **`src.indexOf(t)` 首次出现匹配**（`cellWrapOccurrence`:7601-7611） |
| toggle 语义 | LIFO 游程判定 + FMT-4 链接外壳 + FMT-5b 跨标记外推（3132 起） | 简单「紧邻成对则剥、否则包」 |
| 码内守卫 | FMT-1：选区与 `<code>` 相交 → 拒绝 + toast（7887-7916） | **无**（`cellFormatCtx` 分支在守卫之前 return，7885-7886） |
| 边界吸附 / 跨行拒绝 | 有（7967-8005） | 不适用（单格内无行界） |

分叉本身不必然是缺陷（单元格源码是行内短串，简单模型多数场景够用），但实测命中两处真缺陷：

### FMTB-1 ｜ P2 · 单元格内重复文字：格式化写到首次出现处，不是选中处

- **复现**：单元格「甲乙甲乙」，选中**第二处**「甲」→ 加粗。管道表 raw 得 `| **甲**乙甲乙 |`，HTML 表得 `<strong>甲</strong>乙甲乙`——**加粗落在第一处**（探针 `_m98` B1 + `_m98b` R3f 双表型实锤）。正文同样操作精确落在第二处（`甲乙**甲**乙` ✅）。
- **根因**：`cellWrapOccurrence`（7601）以 `src.indexOf(t)` 定位；`cellPeelAt` 的入口（7722-7723 `src.indexOf(t)`）同根因。选区位置信息（`cf` 上下文）没有传入偏移。
- **影响**：格内含重复词（表格高频：状态列「未开始未开始」、姓名列重名等）时，格式化/清除格式作用在错误的文字上——用户选 B 改 A，且无任何提示。
- **修复方向**：`cellFormatCtx` 已有选区 Range（7594-7596），补传「选中文字在格内渲染文本中的出现序数」（`cf.text` 之前同格文本中 `t` 出现的次数），`cellMutateSrc` 按第 n 次出现定位，替换两处 `indexOf`。

### FMTB-2 ｜ P2 · 单元格内行内码无叠加守卫（FMT-1 在单元格路径缺席）

- **复现**：①管道表单元格 `前\`码甲\`后`，选中码内「码甲」→ 加粗 → raw 得 `` 前`**码甲**`后 ``——码 span 内 CommonMark 不解析标记，**渲染为字面 `**码甲**`**（源码泄漏，与 FMT-1 当初修的破坏完全同型）；②HTML 表 `<code>x</code>` → `<code><strong>x</strong></code>`（探针 `_m98b` R3b/R3b 旁证实锤）。正文同类操作被 FMT-1 拒绝并 toast「行内代码内不支持叠加行内格式」。
- **根因**：`applyFloatAction`（7881-7886）`cellFormatCtx` 分支在 FMT-1 守卫（7887-7916）**之前** return，守卫对单元格路径整体缺席。
- **修复方向**：cell 分支内补同款判定——选区 intersects 格内 `code` 元素（`cf.cell.querySelectorAll('code')`）→ 拒绝 + 同文案 toast；或把 FMT-1 守卫整体上移到 cell 分支之前（守卫本身按选区工作，与块型无关，上移更干净——需验证 `clearfmt`/`delblk` 放行语义不受影响）。

### FMTB-4 ｜ P3 观察项 · 跨块选区：标题计数文案与动作范围不一致

- **现象**（探针 D2）：选区从标题 1 拖到标题 2（跨块），浮条尾部报「**标题 2**，已选 11 字」（`selHeadingCount`:7536 按相交计数），且 h1 的 ⇔ 在列；点粗体后**只有第一个标题块变化**（`# **标题一**`，标题二未动）。
- **判定**：文案暗示「作用于 2 个标题」，实际只作用选区起点块——文案已为跨块场景留位（7533-7535 注释自述），动作未跟上。非破坏性，但误导。
- **修复方向**（二选一）：①动作扩展——按 HDR-1 `applyHeadingLevel` 的 `intersectsNode` 逐块模式，格式动作作用于全部相交块（注意跨块行内映射需逐块重算选区，成本中）；②文案收敛——跨块时尾部降级为「已选 N 字」不报标题数。倾向 ①（全选整篇套格式的需求真实存在），但可与「格式栏是否支持跨块」的产品决策合并考虑。

## 五、结论与登记

**回答用户两问**：

1. **功能是否统一？** 按钮层：**统一**（13 类上下文共用一套工厂与开关，差异全部有设计依据：h1 ⇔、单元格 ＋、特殊块仅删除）。动作语义层：**单元格路径与正文路径分叉**，两处缺陷实锤（FMTB-1/FMTB-2），本质是单元格路径复刻了一套简化版格式化引擎、没有继承正文路径迭代两年积累的守卫体系（FMT-1/FMT-4/FMT-5/边界吸附）。
2. **代码是否一致？** 决策链单点、无复制粘贴式分叉（好）；但**单元格格式化引擎与正文引擎是两套并行实现**（`cellWrapOccurrence/cellPeelAt` vs `wrapSelection` 系列），语义漂移已在重复文字定位与码内守卫两处显形。长期看建议单元格路径复用正文引擎的守卫判定（FMT-1 上移即可覆盖一半），短期按 FMTB-1/2 定点修复。

**登记**（已同步 `docs/未实现BUG与优化清单-v3.30.11.md`）：

| 编号 | 事项 | 优先级 |
|---|---|---|
| FMTB-1 | 单元格重复文字格式化首现错位（管道 + HTML 双表型） | **P2** |
| FMTB-2 | 单元格行内码叠加守卫缺席（FMT-1 分叉） | **P2** |
| FMTB-4 | 跨块选区标题计数文案与动作范围不一致 | P3 观察 |
| TBL-F2 | 单元格「＋」按钮（上轮已登记，本轮 A8/A9 复确认其在列） | P3 |

**回归锚点**：`tests/_m98_fmtbar.py`（按钮矩阵）+ `_m98b_repro.py`（语义甄别），修复后复跑，FMTB-1 验收标准：管道/HTML 双表型选第二处重复文字，加粗/清除均落在选中处。
